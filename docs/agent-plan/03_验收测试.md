# 03 验收与测试｜让“看起来能玩”变成“确实可信”

> 目的：给本人和 Agent 一套**可以操作、可以复现、可以判断过/不过**的标准。P0–P2 执行期间逐渐实现；不要求 P0 就通过全部业务测试。

## 1. 标准测试环境

- 电脑浏览器：能用鼠标复现拖动投圈，检查控制台、WebGL/WASM 加载与 FPS。
- 手机横屏核心视口为 **844×390、667×375 CSS px**。两种尺寸都做模拟测量，至少一部真机补测触摸、安全区和旋转；音频与切后台恢复在对应功能阶段执行。1280×720 供桌面开发。
- 默认采用透视，垂直 FOV30°、俯视30°、偏航0°。正交、透视 FOV25°/35°及其他俯视角仅作调试对照。
- 开发态开关：碰撞线框、路径线、鹅头颈轴线、RingJudge 状态、飞行速度、Throw ID / Goose ID、固定物理 tick、随机 seed、物理慢动作。
- 固定种子：至少 3 套可重复场景；禁止用“随机结果刚好通过”掩盖不稳定。

## 3. P0-A 投掷可达性矩阵

| 编号 | 操作/场景 | 通过条件 |
|---|---|---|
| PA-01 | 两种视口，用鼠标和触摸模拟验证三种手势及取消 | 从合法起手区开始，按住、下拉或斜拉、向前甩均能通过各自输入出手。力度、横向瞄准连续可预测，中心可双向达到 ±40°，手持与实投横移同源。分别在圈心、圈内偏位和圈边验证短拨、稍停松手、按住后前抛。覆盖明显回拉、轻点、第二指、越区松手、取消、失捕获、实际视口变化和转屏。记录抓圈、底带与边缘的可用行程，以及每次手势的发射次数 |
| PA-02 | 固定输入对照发射描述、轨迹预测和 Rapier tick，包含默认与调试阻尼 | 预览和实际出手共用世界发射位置、初速度和当前物理参数。手持悬浮或倾斜属指示表现。量化首碰前轨迹误差及无遮挡地面首碰位置差，保留尺度一致的碰栏样本 |
| PA-03 | 固定八鹅静态布局并保留全部场景碰撞体，逐只搜索和重放 | 每只鹅至少有一组正常手势可输入的名义样本。记录目标、手势数据或可复现参数、初态、首碰对象和步号、鹅头下降穿过环孔及颈区进入环孔的证据。相同输入和初场能复现结果 |
| PA-04 | 复跑最近鹅和 G1～G3 的现行样本，逐只测输入扰动 | 每个目标至少有一个与名义不同且能通过的邻近手势组合，并有失败对照。可从 `aim±1°`、`charge±0.03` 起做诊断，再换算为实际手势的时间、位移或速度。夹紧后与名义初态重复的样本不计。只在极值点通过或可用行程不足时，带数据报人工决策 |
| PA-05 | 两种视口回放近中远正反例，在可用手机上用触摸试玩 | 鼠标与触摸走同一映射。分别记录自动重放和真机证据，真机复核手势切换、长按中断和浏览器栏变化，未复现或未测试项明确列出。回归 PL-01～PL-07 和原物理测试，覆盖暂停/设置中断、有效出手扣一圈、余圈归零后末圈结算及单鹅调试不扣正式圈 |

PA 评估的是入颈路径，P0-2 实现 `RingJudge` 稳定期与 `CAUGHT`。垂直落颈调试预设与地面落点用于诊断。逐鹅覆盖使用正常手势可生成的初状态，三种手势分别验证可用性。

> **状态（2026-11-26）**：P0-A 已由负责人真机签收。PA-01 两视口触摸矩阵 16/16；PA-02 预览/实际误差已量化；PA-03/04 由 8 鹅 × 3 组样本与 81 项自动化测试覆盖；PA-05 真机主观通过，三档成功率、偏转灵敏度终评、拇指遮挡观感三项**未量化**，转入 P1 观察，不计为已验证。

## 4. P0 物理和命中矩阵

| 编号 | 操作/场景 | 期望 | 失败时要记录什么 |
|---|---|---|---|
| PH-01 | 圈按预设速度飞行，落到无遮挡地面 | 路径合理，有弹跳和摩擦，无明显地面穿透 | 速度、姿态、step、CCD |
| PH-02 | 圈正面撞栏杆 / 擦栏杆顶部 | 被实体阻挡或合理反弹，无幽灵穿栏 | 栏 Collider 截面、接触日志 |
| PH-03 | 调整环内孔，向空洞穿过小物体 | 内孔真实存在，不能被实心盘阻挡 | 圈段位置、相邻碰撞体间隙 |
| PH-04 | 正上方将环套过头部，落到颈部并稳定 | RingJudge `CAUGHT` 一次 | 穿越记录、脖颈位姿、稳定时长 |
| PH-05 | 环碰到鹅头顶部 | `MISSED`，头部受力/反弹可见 | 头 Collider/碰撞事件 |
| PH-06 | 环碰到鹅身或翅膀 | `MISSED` | 拍摄截帧与判定日志 |
| PH-07 | 环从颈部侧面贴近 | 无非法穿入、不得计为套中 | 圈中心轨迹、环平面朝向 |
| PH-08 | 进入颈部但稳定期内滑脱 | `MISSED`、不提前 +1 | 时间轴、判定状态转换 |
| PH-09 | 环可能同时接触两个鹅 | 最多一只计数，赢家判定可解释 | throwId / gooseIds / contact order |
| PH-10 | 单鹅依次低头、抬头、左歪头、右歪头；在各动作中投圈 | 同一固定物理 tick 的视觉头颈、Rapier Collider 与 RingJudge 目标位姿一致；动态动作下成功/失败仍符合 P0-2 口径 | 每 tick 姿态快照、头/颈轴线、Collider 变换、RingJudge 目标值及最大差值 |
| PH-11 | 运动鹅靠近静态鹅、其他鹅和围栏 | 主体边界有可验证的阻挡/约束，不把 fixed-fixed 静态重叠或仅接触回调当作阻挡通过 | 刚体类型、碰撞组、最小分离距离、最大穿透深度、修正次数和异常 tick |
| PH-12 | 连续投 100 圈 / 渲染 30 与 15 FPS / 暂停恢复 / 切后台 | 固定物理步下结果不随渲染 FPS 变化；无持续穿模、重复结算、状态丢失或残留刚体 | FPS、物理 tick、物理耗时、帧耗时、误判/穿模/重复结算计数、seed 和恢复日志 |
| PH-13 | 用两种不同的灰盒外观网格消费同一份姿态快照；切换套圈外观材质/装饰 | 只改外观不改头/颈/身体 Collider、RingJudge 目标和套圈物理参数；模型轮廓落在约定的碰撞代理边界内 | 姿态接口字段、模型根节点/单位/朝向、锚点坐标、Collider 参数前后差异、同 seed 判定结果对照 |

**补充：**“100 次全部没有穿模”不等于数学上永不穿透；必须记录最差交叉深度、复现场景和可视异常，确保正式镜头下不可见、判定可靠。

> **历史验收记录（2026-11-26；负责人于 2026-11-27 最终签收）**：PH-04~PH-09 由 `src/judge/ringJudge.test.ts` 25 项覆盖——PH-04 八只静态鹅名义投掷全部 `CAUGHT`（各只结算一次）；PH-05/06 撞头/撞身静止后归因 `head-hit`/`body-hit`；PH-07 侧向水平过颈不计套中；PH-08 稳定期内滑出判 `slip`；PH-09 同 tick 多鹅取最近者、只结算一只。**真机确认**：正例（肉眼看到套进即 HUD 计数正确）、8 只套完后往已退场鹅旧位置再扔不重复计数（无幽灵锁定）。手动复现入口：`?throw=drop&judge=1`（正例）、`?throw=offset&judge=1`（撞头反例）。反例以自动化用例 + 文字复现步骤为准，如需截图归档可后续补。稳定期 0.25 s 仍为实验起点，后续真机长时间试玩可复核是否上调。该判定结果最终全量 106 项测试记录见 report.md；104 项为中间记录。

## 7. 体验与动物友好验证

找 5–10 位使用真实手机的试玩者，记录而非预设结果：

1. 是否无需长说明就懂得怎样拉动/松手？
2. 玩家套不中时，能否准确解释偏短、偏远、撞头还是鹅躲开？
3. 静态场的分步引导与辅助轨迹是否有帮助？单鹅调试直达仅用于内部测试，不纳入新手教学。
4. 普通场与机灵场差别是否明显、可学习？
5. 套中后鹅的反应是否轻松、友善，是否有人觉得在伤害动物？
6. P0-L 选定的镜头在接入完整 HUD、活动鹅后，仍看得清脖子、圈与落点吗？
7. 是否愿意再投圈、再试清摊？哪些动作令人发笑或不舒服？
8. 鹅叫、摊主和环境声关闭后是否能舒适玩？
