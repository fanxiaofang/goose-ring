# 03 验收与测试｜让“看起来能玩”变成“确实可信”

> 目的：给本人和 Agent 一套**可以操作、可以复现、可以判断过/不过**的标准。P0–P2 执行期间逐渐实现；不要求 P0 就通过全部业务测试。

## 1. 标准测试环境

- 电脑浏览器：能用鼠标复现拖动投圈，检查控制台、WebGL/WASM 加载与 FPS。
- 手机横屏核心视口为 **844×390、667×375 CSS px**。两种尺寸都做模拟测量，至少一部真机补测触摸、安全区和旋转；音频与切后台恢复在对应功能阶段执行。1280×720 供桌面开发。
- 默认采用透视，垂直 FOV30°、俯视30°、偏航0°。A 正交、38°/45° 和 C 是调试选项。
- 开发态开关：碰撞线框、路径线、鹅头颈轴线、RingJudge 状态、飞行速度、Throw ID / Goose ID、固定物理 tick、随机 seed、物理慢动作。
- 固定种子：至少 3 套可重复场景；禁止用“随机结果刚好通过”掩盖不稳定。

## 2. P0-L 手机横屏布局矩阵

像素定义、灰盒投影值和量测方法见 [05 布局规范](05_主游戏场景构图与布局执行规范.md)。

| 编号 | 操作/场景 | 通过条件 |
|---|---|---|
| PL-01 | 两种核心视口打开默认透视30°，投影围栏实际网格 | 四角及四面完整，记录围栏、投掷线、手持圈和各侧净空，按用户评审后的预算验收；旧 A 的高度与对称边距数值撤回 |
| PL-02 | 切换大厅/投掷灰盒，开启广告位调试框 | 大厅三项模式入口顶部单行排列；广告位在大厅右侧竖放，与导航、围栏、鹅群、投掷线及热区无相交。投掷态隐藏广告位并释放点击区域。记录两种布局的围栏坐标与净空 |
| PL-03 | 正常透视视角逐只观察鹅群，测包围和局部颈宽 | 记录最小头颈像素和对应鹅 ID，用正常大小手机图检查可读性及遮挡；像素门槛待看图和真机确定 |
| PL-04 | 检查投掷线、静止环、`aim=0/±40°` 与低/中/满蓄力 | 线两端完整且距热区 ≥8 px，手持圈完整且可读。预设投掷的近中远路径可观察，区分 HUD 遮挡与真实越界，保存反例帧 |
| PL-05 | 热区内按下外部松手；热区边界、顶部 UI、第二指、系统取消；鼠标与触摸 | 合法序列只生成一圈；点顶部、热区外起手或轻点取消均无圈。第二指不接管；取消或旋转清除进行中的拖动；拖出热区仍可正常松手 |
| PL-06 | 两尺寸加非对称 inset 与镜像，真机旋转、浏览器栏显示/隐藏 | 取景、UI、热区协同更新；各关键矩形仍在安全区内；报告实际 CSS 视口、四侧 inset、DPR、设备和浏览器 |
| PL-07 | 两尺寸核对大厅/正式场/练习场的信息，并在默认透视下记录辅助关闭/开启 | 大厅显示币、领取、正式圈、兑换、纪录、榜单、帮助、设置、横排模式、开始/继续；正式场显示圈数、本盘、累计、币入口与暂停；练习场显示独立余额、辅助、帮助与返回 |

归档默认透视30° 在两尺寸下的大厅、正式与练习画面、测量层及起手/取消证据。调试模式保留碰撞线框。端点蓄力和系统取消可用短录屏补充。人工通过 P0-L 后开始 P0-A。

## 3. P0-A 投掷可达性矩阵

| 编号 | 操作/场景 | 通过条件 |
|---|---|---|
| PA-01 | 两种手机尺寸，中心和边缘起手；鼠标与触摸 | 按住时长、横向拖动、速度与偏转连续可预测；中心可双向达到 ±40°，手持和实投 X 同源且当前极值约 ±1.15 m。记录边缘行程与取消场景 |
| PA-02 | 固定输入下记录手持姿态、预测与 Rapier tick | 圈、投掷线和实投初始状态的世界坐标一致；预测与实投首碰前的差值可量化。无遮挡地面样本提交首碰位置差；障碍样本确认实际碰撞，记录预测假设 |
| PA-03 | 固定 8 鹅静态布局，保留所有碰撞体，逐只搜索并重放手势 | 每只都用正常可输入的偏转和按压时长，给出一组名义值在真实仿真中从头上下降至颈部区域的证据；记录投掷 ID、初始状态、头顶净空、方向与速度、首碰、颈穿越、是否先撞其他物体。重复同输入能复现 |
| PA-04 | G1 左后失败、G2/G3 低余量与近/中/远样本的输入扰动 | 先复现基线；每个目标至少验证名义值与一个可通过的邻近手势组合，记录偏转和按压容差。建议采样 `aim±1°`、`charge±0.03`，夹紧后与名义样本重复的输入不计。仅极值一点可达须报风险，缺少有效入口则不通过 |
| PA-05 | 两种视口回放近中远正反例，至少一部手机触摸实投 | 鼠标与触摸使用同一归一化映射；相同输入的世界初状态与首碰一致；重新检查 PL-01～PL-06 和原物理测试。逐鹅记录地面可达与真实头颈进入结果 |

PA 评估的是入颈路径，P0-2 实现 `RingJudge` 稳定期与 `CAUGHT`。垂直落颈调试预设用于物理基线，逐鹅覆盖使用正常手势可生成的初状态。

## 4. P0 物理和命中矩阵

| 编号 | 操作/场景 | 期望 | 失败时要记录什么 |
|---|---|---|---|
| PH-01 | 圈按预设速度飞行，落到无遮挡地面 | 路径合理，有弹跳和摩擦，无明显地面穿透 | 速度、姿态、step、CCD |
| PH-02 | 圈正面撞栏杆 / 擦栏杆顶部 | 被实体阻挡或合理反弹，无幽灵穿栏 | 栏 Collider 截面、接触日志 |
| PH-03 | 调整环内孔，向空洞穿过小物体 | 内孔真实存在，不能被实心盘阻挡 | 圈段位置、相邻碰撞体间隙 |
| PH-04 | 正上方将环套过头部，落到颈部并稳定 | RingJudge `CAUGHT` 一次 | 穿越记录、脖颈位姿、稳定时长 |
| PH-05 | 环碰到鹅头顶部 | `MISSED`，头部受力/反弹可见 | 头 Collider/碰撞事件 |
| PH-06 | 环碰到鹅身或翅膀 | `MISSED` | 拍摄截帧与判定日志 |
| PH-07 | 环从颈部侧面贴近 | 无非法穿入、不得计为套中 | 圈中心轨迹、环平面朝向 |
| PH-08 | 进入颈部但稳定期内滑脱 | `MISSED`、不提前 +1 | 时间轴、判定状态转换 |
| PH-09 | 环可能同时接触两个鹅 | 最多一只计数，赢家判定可解释 | throwId / gooseIds / contact order |
| PH-10 | 鹅低头、歪头、抬头中投圈 | 视觉与头颈 Collider 同步 | 每一物理步骨骼/碰撞体差值 |
| PH-11 | 两只鹅挤在一起、靠围栏 | 身体主碰撞体不交叉，不穿栏 | 最小分离距离、修正次数 |
| PH-12 | 连续投 100 圈 / 降低帧率 / 切后台 | 没有持续穿模、状态不双结算、恢复后正常 | FPS、物理耗时、泄露数、异常计数 |

**补充：**“100 次全部没有穿模”不等于数学上永不穿透；必须记录最差交叉深度、复现场景和可视异常，确保正式镜头下不可见、判定可靠。

## 5. P1 操作与练习矩阵

| 编号 | 步骤 | 预期 |
|---|---|---|

| DA-13 | 使用不同设备/浏览器 H5 | 不虚构跨设备同步；没有后端时告知本地保存范围 |

## 7. 体验与动物友好验证

找 5–10 位使用真实手机的试玩者，记录而非预设结果：

1. 是否无需长说明就懂得怎样拉动/松手？
2. 玩家套不中时，能否准确解释偏短、偏远、撞头还是鹅躲开？
3. 辅助轨迹是否有帮助？30 个练习圈是否太少？
4. 普通场与机灵场差别是否明显、可学习？
5. 套中后鹅的反应是否轻松、友善，是否有人觉得在伤害动物？
6. P0-L 选定的镜头在接入完整 HUD、活动鹅后，仍看得清脖子、圈与落点吗？
7. 是否愿意再投圈、再试清摊？哪些动作令人发笑或不舒服？
8. 鹅叫、摊主和环境声关闭后是否能舒适玩？
