# Prompt：P0-2 套入鹅颈与判定（P0-L 与 P0-A 人工通过后使用）

这一步是项目最重要的技术风险实验。先阅读 GDD v1.1 的第 5、6 章、`01_技术方案.md` 与 `03_验收测试.md`，沿用 P0-L 已验收的手机构图和 P0-A 的逐鹅实投证据。

**只做 P0-2**：在已有有孔物理圈基础上，增加简单鹅头（球）、鹅颈（圆柱/胶囊）与身体灰盒，建立有碰撞历史的 `RingJudge` 状态机：

`READY → FLYING → CONTACT / ENTER_NECK → SETTLING → CAUGHT | MISSED`

**必须满足**：
- 圈真正由鹅头上方经内孔穿过头部并进入颈部区域，随后在配置化 0.4–0.7s（待测）稳定期内没有脱落，才算 CAUGHT。
- 撞头、撞身体、擦边、侧面穿颈、落地、稳定期滑脱都不得算成功。
- 不能只比较“圈中心到脖子”的屏幕/世界距离；必须结合朝向/几何穿越历史/真正的 Collider 接触。
- 单次 throwId 最多结算一次；一个圈最多套中一只鹅。
- 保留透明 Collider 和状态机调试视图，能看到从 FLYING 到 ENTER_NECK 的证据；不准为通过测试而禁用关键碰撞体。

**必须实际创建 5 个可复现用例**：合法套中、撞头、撞身、侧穿、滑脱；为每个用例提供输入或调试预设、实际状态转移/结果、截图或录屏保存位置（如可用）。

**发现做不到时**：不要简单改成“碰到鹅就+1”；报告物理原因（环内孔、头宽、接触不稳定、CCD 等）、给出两种替代方案和体验损失，停下来交我决定。

**不做**：鹅群 AI、币与圈经济、练习额度、正式历史累计、美术、平台 SDK。完成后停止。
