## 4. 实施范围

### P0-3A：单鹅可预测头颈动作

- 仅使用现有灰盒几何，不引入 GLB 或骨骼资产。
- 实现低头、抬头、左歪头、右歪头四种可控预设动作；动作有明确起止、幅度和持续时间，能够固定 seed 或直接指定动作序列重放。
- 身体和鹅的整体位置保持可控；本阶段不实现随机漫游、躲避决策或完整群体行为。

### P0-3B：建立唯一姿态数据源

- 为目标鹅提供同一份每物理步姿态数据，至少能表达头部世界位置/旋转、颈部轴线或端点/旋转，以及身体/根节点姿态。
- Three.js 视觉网格、Rapier 运动学目标/Collider 和 RingJudge 目标位置必须消费同一份姿态快照；不得各自用不同公式独立估算。
- 明确固定步时间戳或 tick，使判定使用的姿态与该 tick 的物理状态对应。
- 动态头/颈 Collider 更新必须在对应的 `world.step()` 前完成；物理 step 后读取同一步的环位姿与接触，再把同一姿态快照交给 RingJudge。若实现选择不同的合法顺序，必须说明 Rapier 语义并证明不存在一 tick 延迟。
- 渲染插值不得反向污染物理判定；调试层能够同时观察视觉姿态、Collider 和 RingJudge 目标轴线。

### P0-3C：RingJudge 实时目标位姿

- 将目前构造时静态预计算的鹅头/颈目标，改为每个固定物理步读取对应鹅的实时姿态。
- 保留上一 tick 与当前 tick 的头/颈姿态历史，正确处理旋转和移动下的穿越证据；不能把“当前屏幕重叠”当成入颈。
- 保留 P0-2 的状态机、稳定期、倾斜容忍、失败归因、一投一只、同 tick 选择规则、幂等结果和已退场鹅排除语义。
- 不得为提高动态成功率而擅自扩大内孔、改变颈轴容差、放宽下降方向或静止兜底。若动态姿态揭示 P0-2 几何定义的边界问题，先给出反例和量化数据，交负责人决策。

### P0-3D：有限碰撞边界验证

- 至少验证一只运动鹅与静态鹅、围栏边界的主要碰撞关系；需要时增加少量鹅间相邻布局样本。
- 先说明所选 Rapier 刚体类型、碰撞组、接触检测和运动约束的语义。不能把多个 fixed 刚体之间的静态重叠，或仅有碰撞事件而无位置约束，报告为“已阻挡穿模”。
- 记录鹅主体最小分离距离、最大穿透/重叠深度、边界修正次数及异常 tick；不要求本阶段实现完整 Boids。

### P0-3F：建立未来美术换模不改物理的接口

- 明确区分可见美术网格与不可见物理代理；不得用美术网格三角面直接定义头/颈命中规则。
- 为鹅定义稳定的 `GoosePoseSnapshot`（根/身体姿态、颈根与颈端/中段、头部中心与朝向）；本阶段用灰盒程序动作生成，视觉、Collider、RingJudge 共用同一 tick 的快照。
- 记录未来骨骼适配所需的语义锚点名称/坐标约定；建议预留身体根、颈根、颈中段、头部中心等标记，但本阶段不要求导入正式骨骼模型。
- 套圈的可视网格与物理环分离；视觉材质/装饰变化不得改变现有闭合环 Collider 的中心线半径、管径和内孔。当前 16 段胶囊物理环作为 P0-2 已验收基线。
- 提供“美术网格 + 物理代理 + RingJudge 目标”叠加调试视图。未来 GLB 必须按物理尺寸规范适配；如果美术确实改变头宽/颈粗等关键尺寸，必须走显式参数变更与物理回归，不可静默改动。
- 交付一页未来美术资产规范：单位为米量级、模型根节点/朝向、语义锚点、允许外观偏差、不可越过的碰撞代理边界。

### P0-3E：压力、帧率与画面回归

- 对 100 次连续投圈执行自动化或可重复重放；至少覆盖四种头颈动作、静止对照、成功/失败边界和退场鹅排除。
- 模拟渲染 30 FPS 与 15 FPS（物理仍按固定时间步）；记录物理 tick、物理耗时、帧耗时、异常次数和 RingJudge 结果。不得用改变物理 timestep 的方式模拟低帧率。
- 验证暂停、恢复、切后台/回前台时无大步跳变、重复结算、状态丢失或残留刚体；若宿主环境不支持某项，明确标“未测试”。
- 在 844×390 与 667×375 两种横屏视口、P0-L 已验收的 FOV30°镜头下检查动态头颈、圈和落点可读性。调试角度只用于定位，不得据此替代正式镜头验收。
