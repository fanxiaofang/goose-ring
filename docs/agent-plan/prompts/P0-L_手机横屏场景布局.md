# Prompt · P0-L 手机横屏场景布局

使用前请确认项目负责人已评审 [主游戏场景构图与布局执行规范](../05_主游戏场景构图与布局执行规范.md)。先读根目录 `AGENTS.md` 和 [v0.2 启动提示词](../START_HERE_PROMPT.md)，核对代码及现有改动，列影响文件、方案与验收条件，再开始实现。P0-0/P0-1 直接在现有原型上回归。

1. 以 844×390、667×375 CSS px 和非对称安全区为主，按规范实现相机取景与投影对齐。场地 **14×10 m**（2026-11-26 由 16 收窄，见 [04 D-20261126-003](../04_决策与参数.md)）、当前 8 鹅坐标、投掷线与出手点沿用代码。
2. 做顶部横向入口/HUD 的灰盒、大厅与投掷态的调试切换、仅大厅显示的右侧竖向广告位线框、手持圈触摸区和底部兜底区。广告位按评审通过的尺寸落地。实行合法起手、捕获后越界松手及取消，保留现在的蓄力、角度、速度与 Rapier 逻辑。
3. 保留碰撞、相机调试能力。显示可用区、围栏和关键世界元素的投影尺寸、UI 矩形及热区边界。默认透视（垂直 FOV30°、俯视30°、偏航0°）使用全屏 Canvas 与全尺寸投影偏移。核对大厅及投掷场的正式状态（练习已降级为调试直达），并检查远鹅尺寸和纵深。
4. 执行 [PL-01～PL-07](../03_验收测试.md#2-p0-l-手机横屏布局矩阵)，提供两个尺寸的修正 A 截图、非对称安全区与触摸证据。执行 `npm run typecheck`、`npm run test`、`npm run build`。报告测试环境、结果、截图位置和未验证项。

本阶段验收布局灰盒、既有输入区域和正式场基本流程，覆盖最后一圈结束后的对局详情与返回、暂停后继续和提前结束。真实退币、广告接入、完整战绩统计、摊主和投掷参数优化各按对应阶段安排。交付后暂停，由项目负责人验收。
