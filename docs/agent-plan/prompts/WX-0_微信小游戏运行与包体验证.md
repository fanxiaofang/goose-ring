# Prompt：WX-0 微信小游戏运行环境与包体短验证

> 进入条件：P0-3 已由负责人签收。此任务是一次短小的技术可行性验证，不是正式平台移植，也不实现广告、排行榜或登录。

## 1. 目标

尽早确认当前 Three.js + Rapier 3D + TypeScript 游戏核心能否在微信小游戏运行环境中启动，并获得真实的包体/资源加载数据。H5 继续作为快速调试环境；微信小游戏是首发正式平台；抖音暂不做。

## 2. 开工前

- 阅读 AGENTS、GDD §14、01 技术方案、02 阶段任务。
- 检查当前分支、工作区、依赖版本和 H5 build 输出。
- 先确认可用的微信开发者工具版本、测试 AppID/项目权限；没有权限时明确记录，不得假称已完成。
- 提交最小适配文件清单和验证方案；不得复制整套游戏核心代码。

## 3. 只验证最小切片

1. 微信小游戏入口能启动并创建 Canvas。
2. Three.js 能创建 WebGL renderer，显示现有最小场景/围栏。
3. Rapier WASM 能成功加载、初始化并执行一个简单物理 step。
4. 触摸输入能驱动一次简单的投掷/测试动作；若完整投掷依赖尚未适配，先用最小触摸点/方向反馈证明输入通路。
5. 基础本地存储可写入、读取一条测试数据。
6. 记录主包、每个分包、总包、远程资源大小和开发者工具的校验结果。
7. 检查启动页是否依赖 DOM、window/document、WebAudio 或浏览器文件加载行为；列出需要替换的接口。

## 4. 包体要求

- 以当前微信官方文档和微信开发者工具实际校验为准，确认主包、普通分包、独立分包（若使用）及总包的限制；不要从旧教程复制过时数字。
- 内部预算：主包和总包分别不超过当前对应硬限制的 80%，预留至少 20% 余量。
- 记录原始构建体积、压缩后体积（若工具提供）、主包、分包、总包、远程资源和资源下载量。
- 当前 H5 Vite 单 chunk 约 4.9 MB 的历史警告需要分析，但不得直接把它当作微信主包最终大小。
- 不为“分包”而过早拆分；先识别启动必须资源和可延迟资源。不要远程下载或执行脚本。

## 5. 明确不做

- 不做完整微信大厅、正式 UI、广告、分享、登录、支付、在线排行。
- 不接入抖音小游戏。
- 不为了适配而切换游戏引擎或重写物理系统。
- 不优化尚未测量出问题的美术资源。

## 6. 交付与通过条件

交付一页简短报告：
- 微信开发者工具/基础库/测试 AppID 的实际情况（敏感 ID 不写入仓库）。
- Canvas、Three.js/WebGL、Rapier WASM、触摸、存储逐项通过/失败/未测试。
- 主包、各分包、总包、远程资源大小与工具截图。
- 需要修改的 DOM、文件加载、音频、生命周期等兼容点。
- 若失败，提供最小复现和一个最小修复方案。

**通过条件**：最小 3D 场景能启动，Rapier WASM 能初始化，触摸通路可用，包体数据已测得或因权限受限而明确标记。完成后停下等待负责人确认，不自动扩展成完整平台移植。
