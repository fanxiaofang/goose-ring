# 02 Agent 执行任务与阶段关口（P0–P2）

**执行原则：完成一个、验收一个、再开始下一个。** 下列任务顺序是实现依赖，不是玩家关卡。对应 GDD v1.1 的 P0–P2，不意味着 P3/P4 已定或已开发。

## 通用交付要求

每个任务结束，Agent 必须汇报：

1. 本次实际改动文件与功能；如修改既有结构，说明为何必要。
2. 启动/构建/测试的**真实命令及输出摘要**；做不到的明确写原因。
3. 如何人工复现正例、反例；提供至少 2 张截图或说明录屏保存位置（如果执行环境允许）。
4. 可调参数清单、未解决问题和实际风险。
5. 停在当前阶段，不自动进入下一阶段。

每步确保 Git 可回退；**失败路径也是验收目标**。

## P0-0：创建工程、横屏场景与物理底座

**目标**：证明 Three.js + Rapier + Vite 在 H5 本地正常运行。

**范围**：初始化 `vanilla-ts`；创建 Three scene、OrthographicCamera（俯视角可切 30/38/45°）、地面、围栏（视觉与 Collider 同步）、Rapier WASM 初始化、固定时间步主循环、基础调试面板、鼠标/触控基本事件；屏幕不是横屏时提示旋转。

**排除**：没有鹅 AI、没有玩法、没有广告/商店/UI 大厅、没有正式美术。

**验收**：浏览器桌面/移动模拟可见宽围栏；调整镜头不破坏坐标；物理地面碰撞有效；`npm run build` 与 TS 检查通过；控制台无持续错误；开发态能看物理碰撞调试信息。

**关口**：能安全生成一个测试刚体落到地面，不穿透；若 Rapier WASM 加载失败，先修再继续。

## P0-1：套圈真实物理与飞行操作

**目标**：可投掷一个具有空孔、体积与倾角的物理圈。

**范围**：有孔环体复合 Collider；出手初速度；重力、摩擦、弹性、弹跳和碰栏；底部拖拽/松手投掷；发射起点；圈的销毁回收；显示固定步、环体 Collider、速度与旋转，必要时 CCD。

**排除**：此时暂不判断套中；不加复杂鹅模型。

**验收**：多种力度可产生连续可重复的飞行距离；碰地有响应、碰围栏可弹/停且不透明穿透；圈穿过无障碍空洞时不被假圆盘挡住；多次投掷后资源清理正常；不能把视觉圈做得和 Collider 明显不一致。

**关口**：P0-1 至少录下 3 种碰撞情形（地面、栏杆、不同初始倾角）。若环状 Collider 性能或稳定性严重不足，提交实验数据与备选实现，等待决策。

## P0-2：几何鹅头/颈 + RingJudge 状态机

**目标**：实现**只有合理地套入鹅颈才算成功**。

**范围**：几何头（球形）、颈（胶囊/圆柱）、身体，Collider 与视觉对应；`RingJudge` 状态机；头部上方→颈部的穿越事件；稳定时间；合法/非法命中；开发态日志、测试场景。

**排除**：暂不做复杂 AI、精美鹅或历史累计。

**验收用例**：

- 正面落入、环内孔满足尺寸、稳定超过配置时长 → 成功 1 次。
- 直接碰头、碰身、环边擦过 → 不成功。
- 环从侧面穿到脖子/从背后穿模 → 不成功、并可解释为何。
- 在稳定期滑落 → 不成功。
- 一个环碰到两个鹅 → 最多 1 次有效成功。
- 同一次 throwId 多次接触事件 → 只结算 1 次。

**关口**：**至少 5 种**可手动触发的正反场景有文字/截图证据；若判定不得不采用近似方案，必须标明真实物理和规则补偿的边界。

## P0-3：鹅头颈动作、碰撞同步与压力测试

**目标**：圈可以和真实运动的头颈互动，不出现视觉与 Collider 不一致。

**范围**：一个鹅头做低头/歪头预设运动，Collider 同步；鹅与围栏/鹅与鹅简化阻挡；更新顺序统一；暂停/后台恢复；10～100 次压力测试脚本、低帧率模拟；相机 3 档对比。

**验收**：移动脖子时可见与实际碰撞一致；撞击面不会变成隐形墙；鹅主躯干不穿其他鹅；渲染降到 15–30 FPS 时物理结果不随 FPS 变形；圈落地不会越栏；测试记录异常次数。

**关口**：若有明显物理穿模或“命中假象”，停止增加游戏内容，先定位。

## P1：可用的新手练习场

**目标**：首次试玩者能在手机横屏理解怎样扔圈。

**范围**：3～5 只静止/轻摆头的鹅；练习开始入口；`full/landing/off` 轨迹与预测落点辅助；首次配置化 30 个练习圈（50 为对照值）；练习投圈扣减、退出/刷新恢复；友好的成功/失败反馈；设置中的最小音量/静音；帮助说明。

**必须区分**：开发者可通过 debug 无限投圈，正式玩家练习额度有限；练习无正式总数、排行榜、币库存写入。

**验收**：初次打开有清楚教程；触摸/鼠标拖拽方向和力度可学；轨迹与无障碍地面落点相符；练习圈正确扣减；关闭网页重新打开，额度剩余正确；没有无限练习漏洞；能从设置关闭鹅叫/环境声占位通道（如果对应声音已加入）。

**关口**：真人手机实测后再把 P1 称为“可玩”。如果 30 个圈不够学会投掷，先对照 50，不得擅自开放无限。

## P2：正式游戏核心闭环（不接真实广告）

**目标**：正式套中立即记 1 只、保存、支持清摊和跨天继续。

**范围**：普通/机灵模式，共用正式圈库存，各自独立 Board；每盘初始 8 鹅（可调）；基础漫游、察觉/反应延迟/躲避冷却（按 GDD 的参数原型）；一次投掷对应唯一 throwId；`CAUGHT` 在单次原子本地事务更新玩家历史累计和盘面；清摊/漂亮清摊；换盘、切模式、暂停恢复；个人准确率、按模式总数；简单大厅/HUD/结算卡；币和兑换**配置化模拟**（可根据进度独立开关，不引入真实广告）。

**不做**：摊主指挥、完整 Boids、真实排行、真实微信/抖音 SDK、朋友圈立即分享领币、省份榜。

**验收**：

- 普通鹅套中 → 普通累计 +1、总数 +1；机灵同理。
- 练习套中 → 正式累计完全不变。
- **单只正式套中后立即刷新** → 历史数据和 Board 一致。
- 重复触发一次 hit → 不能双加；换盘和清摊不能二次加数。
- 8/8 清摊 → 清摊次数 +1，累计不额外 +8；可新盘。
- 中途退出明天再来 → 继续同一盘、库存和已套中保持。
- 圈数不足 → 可以暂停/退出/展示补给占位，不强制广告。
- 余额兑换同一命令重复执行 → 不得重复送圈或扣币；P2 仅模拟政策。

**关口**：P2 才成为内部 H5 玩法原型。即使 P2 通过，也不能声称已满足微信/抖音发布条件。
