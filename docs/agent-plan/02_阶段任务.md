# 02 Agent 执行任务与阶段关口（P0–P2）

**执行原则：完成一个、验收一个、再开始下一个。** 下列任务顺序是实现依赖，不是玩家关卡。对应 GDD v1.1 的 P0–P2，不意味着 P3/P4 已定或已开发。

v0.2 顺序为 **P0-0 → P0-1 → P0-L → P0-A → P0-2 → P0-3 → P1 → P2**。当前工作是 P0-L 构图规范评审。P0-0/P0-1 保留既有实现和测试记录，按现有代码做必要回归。

## 通用交付要求

每个任务结束，Agent 必须汇报：

1. 本次实际改动文件与功能；如修改既有结构，说明为何必要。
2. 启动/构建/测试的**真实命令及输出摘要**；做不到的明确写原因。
3. 如何人工复现正例、反例；提供至少 2 张截图或说明录屏保存位置（如果执行环境允许）。
4. 可调参数清单、未解决问题和实际风险。
5. 停在当前阶段，不自动进入下一阶段。

每步确保 Git 可回退；**失败路径也是验收目标**。

## P0-0：创建工程、横屏场景与物理底座（已实现，供追溯）

**目标**：证明 Three.js + Rapier + Vite 在 H5 本地正常运行。

**范围**：初始化 `vanilla-ts`；创建 Three scene、OrthographicCamera（俯视角可切 30/38/45°）、地面、围栏（视觉与 Collider 同步）、Rapier WASM 初始化、固定时间步主循环、基础调试面板、鼠标/触控基本事件；屏幕不是横屏时提示旋转。

**排除**：没有鹅 AI、没有玩法、没有广告/商店/UI 大厅、没有正式美术。

**验收**：浏览器桌面/移动模拟可见宽围栏；调整镜头不破坏坐标；物理地面碰撞有效；`npm run build` 与 TS 检查通过；控制台无持续错误；开发态能看物理碰撞调试信息。

**关口**：能安全生成一个测试刚体落到地面，不穿透；若 Rapier WASM 加载失败，先修再继续。

## P0-1：套圈真实物理与飞行操作（已实现，供追溯）

**目标**：可投掷一个具有空孔、体积与倾角的物理圈。

**范围**：有孔环体复合 Collider；出手初速度；重力、摩擦、弹性、弹跳和碰栏；底部拖拽/松手投掷；发射起点；圈的销毁回收；显示固定步、环体 Collider、速度与旋转，必要时 CCD。

**排除**：此时暂不判断套中；不加复杂鹅模型。

**验收**：多种力度可产生连续可重复的飞行距离；碰地有响应、碰围栏可弹/停且不透明穿透；圈穿过无障碍空洞时不被假圆盘挡住；多次投掷后资源清理正常；不能把视觉圈做得和 Collider 明显不一致。

**关口**：P0-1 至少录下 3 种碰撞情形（地面、栏杆、不同初始倾角）。现存测试与证据见 [04 P0-0/P0-1 参数表和 D-20261123-009](04_决策与参数.md)。后续按 v0.2 进入 P0-L。

## P0-L：手机横屏场景布局验收

**目标**：在 844×390 和 667×375 手机横屏与非对称安全区内，完整看到围栏、八只鹅的头颈、投掷线和手持圈，上方入口与下方操作有独立空间。

**范围**：按评审通过的 [05 布局规范](05_主游戏场景构图与布局执行规范.md) 实现响应式取景、顶部横向入口/HUD 灰盒、底部起手区和仅大厅显示的右侧竖向广告位调试框。用现有世界尺寸、鹅位和物理参数建立构图对照。以透视（垂直 FOV30°、俯视30°、偏航0°）为默认，逐项核对大厅资源/功能入口、正式场 HUD 与独立练习 HUD。容量和摊主活动带按评审结果纳入后续资产预算。

**关口**：[PL-01～PL-07](03_验收测试.md#2-p0-l-手机横屏布局矩阵) 给出两个尺寸测量与截图、非对称安全区和真机触摸证据。对照未达标时记录是哪项及实测值。由项目负责人确认构图后再进入 P0-A。

## P0-A：投掷可达性与操作映射

**目标**：以 P0-L 确认的构图，打通按压、拖动、出手、预览、Rapier 实投与八个静态鹅位的可达链路。

**范围**：核对投掷线、圈的手持和实际出手位置、蓄力与横拖映射、辅助轨迹/地面落点；可重放同样的手势参数。逐只验证真实环体下降越过头部进入颈区。先复现左后 G1 的失败和 G2/G3 的余量瓶颈，再用单变量实测形成候选修正。

**关口**：[PA-01～PA-05](03_验收测试.md#3-p0-a-投掷可达性矩阵) 留 8 只鹅的真实投掷记录、正反例、失败原因和真机输入证据。任何作为正式目标的鹅缺少可重现入口或基本操作容差时交人工决策。P0-2 才引入稳定期和正式套中状态。

## P0-2：几何鹅头/颈 + RingJudge 状态机

**目标**：实现**只有合理地套入鹅颈才算成功**。

**范围**：几何头（球形）、颈（胶囊/圆柱）、身体，Collider 与视觉对应；`RingJudge` 状态机；头部上方→颈部的穿越事件；稳定时间；合法/非法命中；开发态日志、测试场景。

**排除**：暂不做复杂 AI、精美鹅或历史累计。

**验收用例**：

- 正面落入、环内孔满足尺寸、稳定超过配置时长 → 成功 1 次。
- 直接碰头、碰身、环边擦过 → 不成功。
- 环从侧面穿到脖子/从背后穿模 → 不成功、并可解释为何。
- 在稳定期滑落 → 不成功。
- 一个环碰到两个鹅 → 最多 1 次有效成功。
- 同一次 throwId 多次接触事件 → 只结算 1 次。

**关口**：**至少 5 种**可手动触发的正反场景有文字/截图证据；若判定不得不采用近似方案，必须标明真实物理和规则补偿的边界。

## P0-3：鹅头颈动作、碰撞同步与压力测试

**目标**：圈可以和真实运动的头颈互动，不出现视觉与 Collider 不一致。

**范围**：一个鹅头做低头/歪头预设运动，Collider 同步；鹅与围栏/鹅与鹅简化阻挡；更新顺序统一；暂停/后台恢复；10～100 次压力测试脚本、低帧率模拟；在 P0-L 选定的镜头下回归头颈可辨识度，遇到新问题再用调试角度定位。

**验收**：移动脖子时可见与实际碰撞一致；撞击面不会变成隐形墙；鹅主躯干不穿其他鹅；渲染降到 15–30 FPS 时物理结果不随 FPS 变形；圈落地不会越栏；测试记录异常次数。

**关口**：若有明显物理穿模或“命中假象”，停止增加游戏内容，先定位。

## P1：可用的新手练习场

**目标**：首次试玩者能在手机横屏理解怎样扔圈。

**范围**：单只鹅（仅待机动画、原地不动）；练习开始入口；`full/landing/off` 轨迹与预测落点辅助；友好的成功/失败反馈；设置中的最小音量/静音；帮助说明。

**必须区分**：练习场不计圈、可无限投，不消耗正式圈/币，也不写正式总数、排行榜、币库存；正式发行不得借练习场名义接入广告或诱导付费。

**验收**：初次打开有清楚教程；触摸/鼠标拖拽方向和力度可学；轨迹与无障碍地面落点相符；练习不计圈、可无限投，不产生正式圈/币漏洞；能从设置关闭鹅叫/环境声占位通道（如果对应声音已加入）。

**关口**：真人手机实测后再把 P1 称为“可玩”。

## P2：正式游戏核心闭环（不接真实广告）

**目标**：正式套中立即记 1 只、保存、支持清摊和跨天继续。

**范围**：静态/普通/机灵模式，共用正式圈库存，各自独立 Board；每盘初始 8 鹅（可调）；基础漫游、察觉/反应延迟/躲避冷却（按 GDD 的参数原型）；一次投掷对应唯一 throwId；`CAUGHT` 在单次原子本地事务更新玩家历史累计和盘面；清摊/漂亮清摊；换盘、切模式、暂停恢复；个人准确率、按模式总数；简单大厅/HUD/结算卡；币和兑换**配置化模拟**（可根据进度独立开关，不引入真实广告）。

**不做**：摊主指挥、完整 Boids、真实排行、真实微信/抖音 SDK、朋友圈立即分享领币、省份榜。

**验收**：

- 静态/普通/机灵鹅套中 → 对应累计 +1、总数 +1。
- 练习套中 → 正式累计完全不变。
- **单只正式套中后立即刷新** → 历史数据和 Board 一致。
- 重复触发一次 hit → 不能双加；换盘和清摊不能二次加数。
- 8/8 清摊 → 清摊次数 +1，累计不额外 +8；可新盘。
- 中途退出明天再来 → 继续同一盘、库存和已套中保持。
- 圈数不足 → 可以暂停/退出/展示补给占位，不强制广告。
- 余额兑换同一命令重复执行 → 不得重复送圈或扣币；P2 仅模拟政策。

**关口**：P2 才成为内部 H5 玩法原型。即使 P2 通过，也不能声称已满足微信/抖音发布条件。
