# 《鹅有一套》Agent 执行包 v0.1｜从 GDD 到可玩 H5

> 版本：2026-11-22。配套来源：`GDD_v1.1_设计基线.md`（原样复制），其规则优先于本文。  
> 目标：让 Codex / Google AI Studio **逐关口实现并验证**，而不是一条提示词生成完整游戏。  
> **当前交付物是执行资料，不是已经完成的游戏代码。**

## 现在该怎么用

1. 下载并解压整个执行包，放到游戏项目根目录的 `docs/agent-plan/`（也可以先单独放在空目录）。
2. 将本包的 `AGENTS.md` 放到**项目根目录**，让 Codex 阅读它；如果已有 AGENTS.md，请合并，不要直接覆盖。
3. 把 `GDD_v1.1_设计基线.md`、`01_技术方案.md`、`02_阶段任务.md`、`03_验收测试.md` 一起交给 Agent；第一轮只执行 `prompts/P0-0_初始化与场景.md`。
4. 每完成一个阶段：本人打开网页试玩 → 核对验收证据 → Git 提交 → 继续下一阶段。没有实际运行/测试结果，不得宣称“完成”。
5. `04_决策与参数.md` 用来记录真实测试值、未定问题；数值不应直接写死在散落的脚本中。

## 先做什么、后做什么

| 里程碑 | 只需证明什么 | 通过后才能做什么 |
|---|---|---|
| P0-0 技术底座 | H5 横屏场景可跑、相机可调、物理初始化成功 | 加入套圈物理 |
| P0-1 套圈真实物理 | 有孔的圈飞行/落地/碰栏，不是实心圆盘 | 加入鹅头颈障碍 |
| P0-2 套入判定 | 正上方合理套入能成，撞头/侧穿不能成 | 加入活动鹅与同步碰撞体 |
| P0-3 活动与稳定性 | 鹅颈动作+物理同步、低帧率无明显穿模 | 新手练习 |
| P1 练习可玩版 | 有限练习圈、轨迹预测、暂停恢复、教学反馈 | 正式两模式 |
| P2 正式游戏循环 | 8 鹅盘、正式库存、普通/机灵、成功即时记账、清摊/跨天续盘 | P3 角色与氛围 |

**不在 P0–P2 直接做**：正式精美场景、完整 3D 骨骼资产、完整鹅群 Boids、摊主指挥、真实广告、分享奖励、全服/省份榜、多人联机、后端、生产版微信/抖音构建。

## 新手应该了解的三件事

- **“可以跑” ≠ “物理正确”**：模型好看但穿模、判定解释不通，P0 就不能通过。
- **“有按钮” ≠ “功能完成”**：需要实际点击，验证资源扣减、出错恢复、刷新页面的数据一致性。
- **“模拟器能跑” ≠ “微信/抖音能发”**：早期写平台隔离层，实际构建与 SDK 适配另立任务；不承诺 H5 原封不动移植。

## 运行与验收工作流

Agent 应在项目新建后按实际环境确认 Node/npm 版本要求，安装依赖并提交 lockfile；常规命令预计为：

```bash
npm install
npm run dev -- --host 0.0.0.0
npm run build
npm run test
```

`npm run test` 由 Agent 在项目配置内补齐。若 Node/npm 或浏览器无法运行，请明确报告原因，不要凭空编造测试结果。

## 来源与优先级

1. GDD v1.1 的 **【确定】** 不得擅改。
2. 本包的技术实验措施和**【建议】**是可调整实现方案；每次调整要记录理由与风险。
3. GDD 的 **【待测】/【待定】** 必须配置化或保留 TODO，不许冒充已确定需求。
4. 若技术实现证明当前物理设计不可行，应明确给出“失败证据 + 替代方案 + 所牺牲的真实性”，先交人决策，不得偷偷改成碰到鹅就算套中。
