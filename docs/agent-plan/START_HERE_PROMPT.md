请先认真阅读项目中的以下文件（如果不在根目录，则去 `docs/agent-plan/` 下查找）：
- `GDD_v1.1_设计基线.md`：唯一产品需求基线。

- `00_使用说明.md`

- `02_阶段任务.md`
- `03_验收测试.md`

**本次只执行 `prompts/P0-0_初始化与场景.md`；绝对不要自动完成 P0-1、P1、P2 或增加美术、商城、排行榜、广告。**

你的工作方式：
1. 先检查工作目录、Node/npm、已有文件和 Git 状态；如为空项目则初始化 Vite + TypeScript + Three.js + Rapier 3D。不要随意覆盖已有代码。

2. 项目初始化必须遵守 AGENTS.md 中的单仓库
   多平台架构约束。

   本次只初始化 H5 工程。

   不要创建三个独立项目，
   不要复制三套游戏代码，
   不要创建多个 Git 仓库。

   先确认 01_技术方案.md 中的项目目录结构，
   再开始 P0-0 开发。

3. 简述本次要改什么、有哪些风险；对不影响 P0 的未知美术或玩法细节直接采用配置化实验值，不要停下来问我一堆问题。

4. 实际实现一个横屏固定正交相机场景（38° 默认，可切 30/45°），包含大围栏、地面、物理世界和调试面板。

5. 实际运行、构建、进行基本自测（如果环境允许）。

6. 给我一个尽可能简单的本地运行步骤和手机浏览器试玩方法；标注需要我手工验收的事项。

7. 报告文件变更、实际运行/测试证据、未解决问题，并**停下等待我确认**。

8. ## Skills 与工具使用要求

   在开始开发前，先检查当前 环境中已经安装并可用的 Skills。

   优先考虑以下两个 Skill：

   1. `three-webgl-game`
      - 用于 Three.js、TypeScript、Rapier 的游戏开发。
      - P0 阶段优先使用。
   2. `game-playtest`
      - 用于 H5 游戏试玩、界面检查和问题定位。
      - 在具备相应测试能力时使用，不要求必须有 Playwright MCP。

   如果以上 Skills 尚未安装，请检查其来源、依赖和适用性，并向我说明推荐安装方案。未经确认不要自动安装额外工具。

   关于项目专属的 `goose-physics-qa` Skill：

   - 当前不要求立即创建。
   - 先按照 `03_验收测试.md` 完成套圈物理和碰撞测试。
   - 等测试规则和脚本稳定后，再考虑封装为独立 Skill。
   - 不要为了创建 Skill 而延误核心游戏开发。

   若当前工具不足以完成自动化试玩，应提供人工验收步骤，并如实报告未测试的项目。

   Skills 不得覆盖 `AGENTS.md` 和 GDD 中已经确定的项目约束。

硬要求：真实 3D 空间（Y 向上、XZ 地面）；不可用纯平面 2D 冒充纵深；不允许用无来源的素材冒充已完成美术；测试做不到就说没有测试；本阶段不许生成整款游戏。文档中的【待测】数值只能当默认实验参数。
