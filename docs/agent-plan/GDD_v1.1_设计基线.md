# 《鹅有一套》游戏设计说明书（GDD）

> **版本**：v1.1（设计基线 / 修订待验证项）  
> **日期**：2026-11-22  
> **定位**：个人开发、轻量 3D 物理休闲小游戏  
> **首发验证**：手机横屏 H5；**目标平台**：微信小游戏、抖音小游戏  
> **一句话创意**：在中国民间庙会的套鹅摊，向一群会走动、会歪头、会调皮回应、还可能听摊主指挥的虚构友好大鹅投圈；稳稳套中一只就立即记一只，挑战清摊、提高命中率、积累自己的套鹅纪录。

**阅读说明**：本文是整合此前讨论后的完整游戏设计基线，而不是“所有功能都已拍板”的开发合同。用 **【确定】** 标记用户已明确认可的方向；**【建议】** 为首版可执行方案；**【待测】** 为必须通过手机试玩调参的内容；**【待定】** 为需后续选择、平台核验或尚不适合开发的设计。文内数值默认属于设计起始值，不等于真实动物行为学参数，也不代表平台规定。

## 01. 产品定位与设计边界

### 1.1 核心定位

- 【确定】这是一款以**中国庙会、民间游乐摊、乡镇集市文化**为氛围来源的 **横屏、固定视角、轻技巧** 休闲游戏；**不强制限定为 1990 年代**。复古感可作为艺术语言，而非历史还原任务。
- 【确定】核心动作是 **扔套圈，套中鹅的脖子**；鹅不是静止靶，会自然活动，并在特定条件下躲避。
- 【确定】**不采用传统“第 1 关—第 2 关—通关解锁下一关”的强关卡制**；练习、普通、机灵是入口/难度类别，具体名称可调整。
- 【确定】玩家看到并累积的是**有效套中的真实只数**，不是不同品种的虚构分值；成功判定一旦完成，应即时更新个人档案并持久化。
- 【确定】优先完成横屏 H5 原型；架构预留微信、抖音小游戏的适配可能。
- 【确定】坚持**动物友好、轻松无伤害**的艺术表达：不模拟真实动物恐惧、疼痛、绞勒、挣扎、受伤和捕获售卖。
- 【建议】核心体验优先级：**投掷可学习性与公平性 > 鹅的个性互动 > 轻松庙会氛围 > 成绩与社交 > 商业化**。

### 1.2 核心差异点

不是简单地把传统套圈的奖品换成活体动物，而是将“套鹅”**游戏化为安全、俏皮的虚构鹅群互动**：

1. **投掷有技巧**：方向、力度、飞行时间、姿态与落点具有可学习规律。
2. **鹅会有性格地反应**：发呆、躲圈、歪头、模仿摊主、得意地叫一声。
3. **成功即时累计**：圈达到稳定套入条件，马上增加个人累计，不依赖一盘结束。
4. **清摊是自选挑战**：同一鹅盘全部成功，可庆祝和记录，但不是必须过关。
5. **有开放舒适的庙会空间**：围栏与鹅群是视觉主体，少量招牌、摊主、喂食/饮水设施提供生活感；不是一堆大棚和装饰物。
6. **动物友好的喜剧反馈**：失败时鹅可以“得意”，成功时鹅也安全自在，不以动物受苦制造刺激。

### 1.3 目标玩家与典型时长

- 面向熟悉民间套圈、庙会、赶集文化的休闲玩家，以及喜欢动物拟人化互动、轻量物理挑战的人。
- 【建议】一次短访问可只投 3～10 个圈，不强制必须耗尽库存、也不要求完成一盘才结算。
- 【待测】单次动作可先按准备 1～3 秒、飞行 0.5～2 秒、反馈 0.5～1 秒的节奏原型测试。
- 这不是现实活鹅处置模拟器，不能呈现对动物的惊吓、勒紧、窒息、捆绑、受伤等写实反应；鹅应像庙会里的**友好、聪明的虚构互动角色**。

#### 1.3.1 动物友好表达守则（重点新增）

- **视觉**：使用偏风格化的 3D 鹅，眼神有生命力、姿态舒展；环境干净，提供水和食物；不使用动物受伤、束缚或惊恐的画面。
- **套圈材质**：圈表现为轻巧、柔软、无收紧机制的彩色游戏环；有效套中后可轻轻挂在颈部外侧，或在结算光效中迅速淡出，**不模拟绞勒和压迫脖子**。
- **动作与反馈**：命中后先愣一下、轻轻缩脖、歪头或得意地甩头，随即自然离场；不能尖叫求救、痛苦挣扎、摔倒抽搐。
- **失败与反击**：鹅可以用歪头、昂首、轻拍翅膀、短促俏皮叫声“回敬”玩家；目标是调皮的互动，不是把鹅塑造成受虐对象。
- **文案**：避免“抓到卖掉、挣扎、勒住、抓捕成功”等措辞；主界面可用轻量说明“本游戏为趣味动画互动，鹅鹅不会受到伤害”，不做冗长说教。
- **真实鹅/用户反馈**：不采用真实动物受惊录像或痛苦录音；正式上线前做专门的舒适度测试。如仍明显引起不适，考虑进一步把鹅设定为虚构庙会鹅角色/吉祥物。

#### 1.3.2 “鹅嘲讽玩家”初步设计（暂定）

只定义行为方向，不先拍板具体台词或频率：

| 事件 | 鹅的友好反应示例 | 设计边界 |
|---|---|---|
| 圈落偏 | 歪头看一眼、短促“嘎？” | 不连续重复刷屏 |
| 连续 2～3 次未中 | 某只鹅昂首摆出得意姿势 | 不让玩家感觉被羞辱 |
| 漂亮地躲过一圈 | 轻拍翅膀、扭头看同伴 | 不表现真实恐惧 |
| 玩家套中 | 被套的鹅先愣一下，再轻轻晃头，旁边鹅好奇围观 | 不要痛苦叫声 |

【建议】先用表情和动作表达，必要时增加 1～2 字的小气泡或俏皮叫声；不要让鹅一开始就完整说人话。增加台词冷却、可关闭鹅叫与提示音，避免嘈杂和嘲讽过频。此项是否真正增加乐趣，留给 P2/P3 试玩验证。

### 1.4 首版明确不做

开放世界庙会、真实动物伤害/围捕贩卖表现、多人实时同屏、复杂经济养成、鹅的繁育系统、复杂 AI 学习模型、多个操控摊主的按钮、角色换装商城、跨平台账号联通、地区/省份榜、广告收益优化系统。

## 02. 游戏世界与美术方向

### 2.1 场景设定

- **题材**：中国庙会、民间游乐摊、乡镇集市；不规定具体年代。可保留自然的怀旧感，但不强调对某个年代的写实还原。
- **主体**：**宽敞、整洁的套鹅围栏**占据视觉主区域。围栏内有 8 只左右（待测）可观察、可活动的鹅，地面平整，鹅群之间留有合理间距。
- **摊主**：可在围栏内**专门划定的活动带/安全侧区**待机、转身、走动、招呼玩家；摊主的模型、活动范围和碰撞体不能突然遮挡或误伤投圈判定，也不允许占据大部分鹅群空间。
- **生活装饰**：围栏角落可见一个低矮食槽与一个饮水盆，清楚传达鹅被照顾的感觉；需避开核心投圈轨迹和目标区，防止玩家频繁投中装饰物。
- **招牌与氛围**：保留一个不太大的中文摊位招牌、少量旗帜/灯光和远处围观人群；大棚、木桌、整排灯泡和繁杂陈列**不是必需场景组件**，如果占地方或挡视线就删除。
- **卫生与安全视觉**：清洁、舒适、轻松，不呈现脏污羽毛、受伤鹅、狭窄拥挤的真实动物拘禁感。
- **原创要求**：不复制同类小游戏的品牌、招牌、人物、语音和 UI。

### 2.2 画面结构

固定摄像机从围栏外看向鹅群，横屏 16:9 初始版。**鹅栏与鹅群应成为画面绝对视觉主体，而非背景装饰。**

| 画面区域 | 内容 | 设计约束 |
|---|---|---|
| 中央约 60%～70% 可视面积【待测】 | 鹅群、围栏内部活动空间、飞行/落圈反馈 | 绝对优先，不被大棚、招牌、人物大面积挡住 |
| 下沿约 15%～22%【待测】 | 投圈起点、手势区域、力度/方向提示 | 手指操作区不应被按钮占用 |
| 上沿窄信息带 | 当前盘 `X/Y`、个人累计、圈库存 | 尽量轻量，信息可读，留手机安全区 |
| 场景角落/边缘 | 摊主活动带、食槽、饮水盆、小招牌 | 不侵占主体，避免影响命中判断 |
| 非操作界面/暂停面板 | 领币、兑换、榜单、模式选择、完整设置、玩法说明 | 不把所有入口硬塞进游戏上沿 |

【建议】用 UI 调试开关实时显示安全区、鹅栏屏幕占比、触控热区，重点检查 16:9、18:9 和带异形安全区的横屏设备；避免用简单裁切令鹅头、围栏和按钮超出屏幕。

### 2.3 相机

- 【确定】固定视角，使用 **3D 空间 + 正交投影（OrthographicCamera）** 的 2.5D 呈现。
- 【建议】初始俯视角 **38°**（相对于水平面），相机水平偏转 0°～8°。
- 【待测】30° / 38° / 45° 三档对比：能否同时看清鹅头、鹅脖、圈的落点和鹅群纵深。
- 游戏中不需要玩家自由旋转相机；必要时仅允许少量整体取景偏移，不改变判定规则。
- 正交相机负责投影；**真实前后关系、碰撞、落点和套入几何仍在 3D 坐标中处理**。

### 2.4 基础美术资产

- **场景必需**：足够大的围栏、干净地面、鹅栏低矮障碍、少量外围环境。
- **场景增强**：小型中文招牌、角落食槽和饮水盆、简化远景、少量节日装饰（棚架、木桌、灯串均可选，不能压缩主体）。
- **互动必需**：可复用 3D 鹅模型与骨骼、鹅头颈碰撞体、3 类性格/外观变体、可投掷套圈、清晰影子和轻量成功/失败反馈。
- **人物**：摊主可在围栏内安全活动带走动/转身；第一轮物理原型可先用几何人偶占位，不沿用另一项目的“外星摊主”设定。
- **UI**：当前模式、盘面 X/Y、历史累计、剩余圈、币余额/领取入口（若采用币制）、帮助、辅助、设置、榜单、结算卡。
- **音频**：环境人声、摊主台词、投掷/碰撞音效、轻量鹅叫（独立可关闭）。

## 03. 玩家核心循环（无传统关卡）

### 3.1 主循环

**打开游戏 → 进入练习或正式模式 → 观察鹅群 → 拖拽/松手投圈 → 鹅按个体状态反应 → 物理碰撞与套入判定 → 成功即时 +1 并保存 / 失败即时反馈 → 继续投、暂停或换盘 → 清摊时额外庆祝 → 下次返回继续。**

- **练习模式**：第一次进入可免费获得一次性**30 个练习圈**（【建议，30 与 50 待 A/B 测试】），只在练习模式扣减；完整轨迹与预测落点默认开启。练习记录不影响正式累计和排行榜。
- **正式模式**：消耗独立的正式圈库存；没有“每局固定 20 圈”的概念，玩家不必一次耗尽当前持有圈数。
- **即时统计**：一只鹅满足 `CAUGHT` 成功条件时，立即将当前盘进度、对应模式累计和历史总数作为**一次可靠提交**写入存储，然后确认画面中的 `+1` 反馈；**绝不等换盘或清摊后统一发放鹅数**。若写入失败，应提示未保存并重试，不得显示已经永久到账。
- **换盘/清摊**：只影响当前盘状态及清摊成就，不回滚既得累计。

### 3.2 三个独立概念

| 概念 | 定义 | 是否过关 | 是否跨天保留 |
|---|---|---|---|
| **模式** | 限额免费练习、普通鹅、机灵鹅 | 不需要 | 保留选择与练习额度 |
| **当前鹅盘 Board** | 一个模式里当前生成的一批鹅 | 可清摊，不是强制关卡 | 【建议】保留 |
| **个人档案** | 累计套中、总投圈、命中率、清摊次数 | 不适用 | 永久保留 |

### 3.3 鹅盘的开始、继续、换盘

- 进入正式模式时，如存在未完成的鹅盘，默认选择 **继续当前盘**；不存在传统闯关条件。
- 如当前盘已清摊，自动进入结算，点击“再来一盘”生成新鹅盘。
- 玩家可以主动“换一盘”；这将放弃当前盘的**清摊进度**，但已入账的鹅数不回滚、已消耗套圈不返还。
- 同一只鹅在同一盘中只允许计数一次，成功后以轻松、无伤害的动作退到待领奖区域，避免反复刷同一只。
- 普通鹅、机灵鹅各保留一盘状态；切换模式不能混用盘进度。
- 保存内容是当前盘种子、仍未被套中的鹅 ID、已用圈数及关键状态；无需逐帧保存随机移动位置，恢复时可按安全位置重建鹅群。
- **成功即时记账**：圈状态确认为 `CAUGHT` 时，使用唯一投掷 ID 和鹅 ID，在同一次可靠提交中保存 `boardCaught`、`caughtNormal/caughtClever`、`totalCaught` 与相应日期维度，不等待盘结束。

### 3.4 一次访问的结束条件

**正式模式没有“每局 20 圈”，也没有必须完成一局才结算成绩。** 玩家可随时暂停或离开；圈库存不足时可打开补给入口或退出，下次继续当前盘。**清摊结算卡是额外庆祝与汇总，不是套鹅数量到账的条件。**

## 04. 模式与难度

| 模式（暂用名） | 鹅的行为 | 辅助 | 资源消耗 | 统计 |
|---|---|---|---|---|
| **练习场** | 3～5 只静止或轻微摆头的鹅，帮助建立手感 | 完整轨迹 + 落点环，允许关闭 | **消耗独立练习圈**；首次建议 30 个免费，非无限 | 不计正式累计和榜单 |
| **普通鹅场** | 缓慢漫游、轻度躲避、个体反应较慢 | 默认简化/关闭【待测】 | 消耗正式圈库存 | 普通模式累计 |
| **机灵鹅场** | 更高察觉概率、更快躲避与更灵活的动作；摊主联动后期引入 | 默认关闭完整轨迹【待测】 | 与普通场共用正式圈库存 | 机灵模式累计 |

### 4.1 命名与入口

以上三个名称仅为占位，后续可改成更有庙会味道的口语名字。**玩法只有练习 + 两个正式难度，没有“需要依次通关”的强关卡体系。** 原来的散养摊、机灵摊、鹅王摊不做三级通关；漫游、躲避和摊主指挥是难度参数及后续事件。

### 4.2 练习资源：必须有限，但也不能成为新手障碍

- 【用户方向已确定】练习场**不再无限免费投圈**；需要有限的练习额度，与正式圈和庙会币分开。
- 【建议测试值】初次进入获得**30 个练习圈**。如果 30 个不足以掌握两种操作变量，可以测试 50 个，但不默认无限。
- 【建议兜底，待测】用完首次额度后，可以每天补充少量练习圈（例如 5 个），避免新玩家隔几天回来连教程都无法练；不计正式成绩、不触发广告收益。**这一每日补充不是已确定规则，可在 H5 试验开关控制。**
- 练习额度不会转换为正式圈，不得计入套鹅累计、清摊次数与排行榜。允许练习期间随时退出，剩余额度持久化。
- H5 **灰盒调试构建**可以通过开发开关投无限圈以测试物理；这一能力必须与面向玩家的有限练习规则隔离，不能出现在正式发行版本。

### 4.3 难度平衡原则

- 【建议】首版同一模式内部采用固定、公开的概率范围；最后一只鹅不能暗中改变闪避率。
- 两种正式难度主要来自鹅的察觉率、反应延迟、灵活度和躲避冷却，不应改变玩家手中同一种圈的物理规则。
- 【待测】正式场每盘初始 8 只鹅；在实际手机横屏视野、鹅身体大小与重叠情况确定后再测 6～12 只。
- 【建议】机灵场初期可以直接选，不要求先通过普通场。
- 为了公平，正式榜单需要记录模式、assistLevel 和投掷次数，避免不同辅助强度的结果被误当成相同挑战。

## 05. 套圈操作与飞行物理

### 5.1 操作模型

- 【建议首版】**拖拽蓄力、左右修正，松手投掷**。
- 玩家手指在画面底部操作区按住套圈，拉动距离映射力度，左右偏移映射方向。
- 触摸点不能被 HUD 阻挡；投掷只在合法操作区域开始，松开有效区域仍能完成投掷。
- 暂不要求玩家控制圈的旋转角度；初始姿态与微小变化由程序决定。
- 另一候选操作“直接向前划甩圈”，保留供 A/B 试玩，不与首版同时实现。

### 5.2 物理需求

套圈必须具有可观察的 **重力、抛物线、速度、姿态、弹跳、摩擦、与鹅及围栏的碰撞**。建议使用 Three.js 做渲染，Rapier 3D 做刚体模拟；不要将“视觉上的抛物线”与“真正的碰撞结果”分开到互相矛盾的系统里。

- 圈：动态刚体；环体可以用若干段简化碰撞形状构成，避免用实心圆盘 Collider。
- 鹅：由行为与骨骼动画驱动的对象，身体/颈部使用随动作更新的简化碰撞形状，不做完整布娃娃动力学。
- 地面、围栏：固定碰撞体。围栏的每段边界应覆盖真实可见尺寸；不能让圈从栅栏缝、栏顶或地面无反馈穿过去。
- 食槽、饮水盆、摊主安全活动区：根据位置做非目标障碍或合理避让；不能让视觉模型遮挡目标但物理上不存在。
- **鹅与鹅**：移动时需同时有分离/局部避障和必要的实体接触纠正。Boids 分离不是最终的防穿模保证。
- 使用固定物理更新步长，必要时为高速圈启用连续碰撞检测（CCD）、物理子步进及合理的碰撞厚度，降低高速穿模；对静态地面与栅栏的精度做专项验证。
- **鹅头颈与身体**随骨骼动画更新的碰撞体必须在正确的物理帧中同步；不能出现看起来鹅已低头但物理颈还留在原处的“隐形墙”。
- **套圈间**：正式是否保留落地旧圈待定；如保留，必须有圈与圈的碰撞，否则在结算后受控回收，避免圈堆叠造成穿模和性能问题。
- 圈的物理体积、质量、阻尼、弹性、角速度及投掷映射需要统一调试面板。

### 5.3 新手轨迹与落点辅助

- 完整辅助：预测抛物线 + 预测落地环。
- 简化辅助：只显示预计**无碰撞情况下**的首次地面落点环。
- 无辅助：显示基础方向/力度，但不画完整路径。
- 轨迹与落点依据当前输入、重力、出手姿态预测；**不自动追踪会移动的鹅，不保证套中**。
- 正式模式的辅助限制尚未定案，先将开关配置化；如果排行榜比较成绩，应保留 assistLevel 字段以便按同规则比较。
- 预测画面不应该遮住鹅颈或误导玩家认为圈可穿过鹅头、围栏。

### 5.4 圈与鹅颈尺寸关系

圈的**有效内径**必须大于套入过程中要经过的鹅头/颈部有效横截面，并留有小幅动画容错；仅规定“圈内径为脖子直径的 1.8～2.2 倍”可能不足以保证能过鹅头。因此应先测量模型的 **头部最大宽度、颈部宽度、圈厚度和可用倾角**，再调节尺寸。目的不是模拟现实尺寸，而是做到玩家视觉上理解的“能套但不容易套”。

### 5.5 可见物体不穿模：明确验收边界（新增）

- **圈 ↔ 鹅头、颈、身、翅**：不出现从视觉模型直接穿入/穿出；套圈必须经过合理的开放内孔套入路径。
- **圈 ↔ 围栏、地面、食盆/水盆**：根据物体是否需要参与碰撞设置实际接触，不能“看起来被挡住但圈穿过去”。
- **鹅 ↔ 鹅**：身体不能互相穿透；允许羽毛或非刚性装饰轻微视觉重叠，但主躯干和脖子不应互插。
- **鹅 ↔ 围栏/摊主**：鹅不能越栏或走进摊主身体；摊主走动区与鹅的避让规则应协调。
- **技术底线**：通过合适的简化 Collider、固定步长、必要的 CCD、骨骼同步、接触纠正以及异常回退解决；不要承诺“任何设备任何情况下 100% 数值零穿透”，目标是**正式镜头下无明显穿模、命中和碰撞结果可解释**。
- **验证**：连续投掷 100 次、低帧率模拟、多个鹅挤在角落、颈部快速低头、圈擦围栏、圈落地叠加、切后台恢复等都应单独测试。

## 06. 套中判定（本游戏的技术核心）

### 6.1 成功定义

**只有圈真正从合理方向越过鹅头、进入颈部区域，并在短暂稳定期内没有甩脱，才算套中一只。** 擦中头、撞到身体、仅落在鹅背上、从侧面穿透颈部都不算成功。

### 6.2 推荐状态机

`READY → FLYING → CONTACT / ENTER_NECK → SETTLING → CAUGHT | MISSED`。

- `FLYING`：正常刚体飞行、检测多段碰撞。
- `CONTACT`：物理接触但尚未认定套入。
- `ENTER_NECK`：满足从头部上方到颈部的几何穿越条件。
- `SETTLING`：进入 0.4～0.7 秒的待测短暂稳定时间，鹅可产生缩脖、惊讶和轻微甩动。
- `CAUGHT`：正式计数一次，播放反馈；圈切换为绑定在颈部的稳定视觉对象或受控约束，避免关节物理抖动。
- `MISSED`：落地、从颈部滑落、被甩掉、越界等；只扣圈，不加鹅数。

### 6.3 几何与公平性

- 不能仅凭圈中心到脖子的距离判断命中。
- 判断圈相对于头颈轴线的穿越方向、圈平面角度、内孔是否容纳颈截面，以及实际接触历史。
- 需要考虑鹅低头和歪头后颈部的骨骼变换；命中区域随动画同步移动。
- 一次投掷最多计中一只鹅；同一只鹅不能被同一圈重复触发成功。
- 只要判定为成功，就及时播放清晰反馈；如果因为判定阈值造成“看起来中了却没中”，优先调整可读性/容错而非盲目增加真实性。
- 动画上要把鹅呈现为被轻巧地套上圈、愣一下、歪头或甩甩脑袋，而不是受伤或被勒紧。
- 套中成功后，圈的视觉状态应保持宽松、可在轻微光效中淡出；鹅自行愉快走到旁边休息区，不出现“被拖走、被捆绑、售卖”的演出。

### 6.4 最小物理验收

不需要一开始就做漂亮大鹅。先用“柱状颈部 + 球状头部 + 刚体套圈”的灰盒实验验证：正面准确抛入可以成功、撞头反弹不能成功、从侧面穿模不能成功、躲避造成的擦边结果稳定、慢速/快速帧率下结果一致。

## 07. 鹅的行为系统与性格

### 7.1 性格属性的清晰划分

| 属性 | 定义 | 作用时点 |
|---|---|---|
| **服从率 obedience** | 是否响应摊主的指挥动作 | 收到摊主信号后 |
| **察觉率 awareness** | 是否察觉一个可能飞向自己的套圈 | 套圈进入威胁感知区 |
| **灵活度 agility** | 躲避动作的速度、幅度与执行能力 | 已作出躲避决定后 |
| **反应延迟 latency** | 从察觉到真正开始动作的延迟 | 反应开始前 |
| **移动速度 walkSpeed** | 漫游速度与加减速 | 普通游走阶段 |
| **躲避冷却 dodgeCooldown** | 两次强躲避之间的最低间隔 | 避免连续作弊式闪避 |

特别区分：察觉率不是灵活度；察觉但动作慢也可能被套中。**反应率**在设计用语中统一改称 **察觉率**，避免与反应延迟混淆。

### 7.2 三种游戏化原型（非真实品种结论）

| 原型 | 服从率 | 察觉率 | 灵活度 | 行为特征 |
|---|---:|---:|---:|---|
| 呆呆鹅 | 20% | 25% | 30% | 发呆、迟钝、比较容易套 |
| 机灵鹅 | 50% | 75% | 85% | 对投掷敏感，动作快 |
| 听话鹅 | 90% | 50% | 65% | 更可能模仿摊主指令 |

以上是**原型调试示例**，不是动物行为学事实。美术可采用白鹅、灰花鹅、大体型鹅的不同外观；真实鹅的品种名称需另查权威来源后再使用，不根据品种直接推断智力和性格。

### 7.3 行为状态机

`IDLE（发呆） / WANDER（漫游） / GRAZE（啄地） / LOOK（张望） / ALERT（警觉） / DODGE_LEFT / DODGE_RIGHT / DUCK（缩脖低头） / CAUGHT（已套中） / EXIT（退场）`。

- 常态：每只鹅有独立的 idle / 漫游 / 啄地时长与随机种子。
- 发现危险：根据物理轨迹预测圈是否接近鹅的活动范围，按察觉率决定是否感知。
- 被感知后：等待独立的随机延迟（【待测】0～0.45 秒），选择一种可执行动作。
- 动作选择：可低头、歪头、侧移；动作存在持续时间与冷却期，不可瞬间反悔切换最优动作。
- 套中时：缩一下脖子、愣住、甩动但不伤害，成功后退到边缘。

### 7.4 反作弊式公平规则

- **不根据圈的最终命中结果回头修改鹅行为**。
- 鹅必须先察觉、经过延迟、做出可见动作；不允许最后 0.02 秒完美瞬移。
- 动作能被玩家看到，有前兆，可通过“抓时机”提高命中率。
- 随机性决定会不会尝试躲和躲的方式，不应替代玩家投掷技术。
- 调试中应记录 `throwId / gooseId / perceived / responseDelay / action / success`，方便定位“不合理闪避”。

### 7.5 鹅群移动：简化 Steering / Boids

使用 **漫游 + 聚合 + 分离 + 边界回避** 四个合力，不做复杂真实动物心理模拟。

- 漫游：每只鹅在围栏内选择局部目标，间歇走停。
- 聚合：适度靠近邻近鹅，避免散得太远。
- 分离：两只鹅过近会互相避让，不能模型重叠。
- 边界：提前转向，不冲入围栏。
- 个体差异：不同走速、方向、停顿、动画起始偏移，**绝不全员同步**。
- 聚合与分离是运动偏好，不是碰撞检测替代品；鹅之间还需要最小安全距离、接触纠正和围栏约束。
- 可选的“鹅得意回应”属于短时行为事件，应与躲避/移动状态机协调，且不会产生瞬移或模型交叉。
- 【建议】8～12 只鹅的规模优先使用邻域简化计算，不引入大型 AI 框架。

## 08. 摊主与鹅群的联动

### 8.1 角色定位

摊主负责庙会氛围、解说和后续特色挑战，不是第一阶段必须完成的复杂 NPC。

### 8.2 首版基本行为

摊主**位于围栏内的安全活动带**，可以待机、转身、走动、招呼玩家、说原创口语台词。必须限制行走区域、与鹅群保持合理避让、不突然遮挡关键鹅颈；摊主不是目标，投圈击中摊主时只做轻松的非伤害性反馈。可用基础 3D 骨骼角色，但物理原型允许几何人偶占位。

### 8.3 后续联动（第二/第三阶段）

- 摊主发出可听到、可看到的预警动作：低头、歪头、侧身、吹口哨。
- 鹅根据自身 **服从率** 决定是否模仿，另叠加个体动作延迟。
- 并非所有鹅同时响应；少量鹅发呆、走神、反其道而行，形成幽默感。
- 玩家可以观察指令与鹅动作节奏，等待它们抬头或抓住不听话个体的空档。
- 指挥动作必须有冷却，不允许摊主无限阻挡玩家。
- 【待定】“赶鹅”按钮：未来若测试表明鹅群过度聚集或有操作收益，再考虑带冷却的左右驱赶信号，首版不做。

## 09. 清摊、漂亮清摊与退出恢复

### 9.1 清摊规则

- 一盘有固定若干只鹅（原型【待测】8 只）。
- 成功套住一只，该鹅从“未完成鹅盘”中退出，并计入当前盘 `caughtCount` 和玩家累计 `lifetimeCaught`。
- **清摊成功**：本盘所有鹅均被有效套中；不要求当天完成，也不要求限定使用圈数。
- **即时到账**：每一只达到 `CAUGHT` 时即将累计数写入个人档案与本地持久化；清摊时只增加清摊次数、播放庆祝，不重复添加本盘鹅数。
- 清摊立即展示庆祝反馈；累计只数不增加额外虚构奖励。

### 9.2 漂亮清摊

- 在同规格盘面下，用较少的圈全部套中，记为“漂亮清摊”。
- 【待测示例】8 鹅盘投掷不超过 15 次完成；实际阈值用玩家测试和盘面统计决定。
- 若跨天接着套，**已用圈数仍累计到同一盘**；不允许隔天清零次数来刷漂亮清摊。
- 建议保存最好的一盘清摊用圈数，未来才考虑单独的效率榜。

### 9.3 存档边界

- 玩家每次**正式套中**后即提交成绩记录，不能等结算卡出现；离开网页/切后台时额外保存关键盘面信息。
- 建议使用唯一 `throwId`、`boardId`、`gooseId` 形成**幂等提交**：同一圈不能重复奖励、同一只鹅在同一盘只记一次。关联更新包含盘面完成集合、模式累计、总累计、月度统计和待落盘事务状态。
- 扣圈与投掷结果需要协调：投掷开始即记录待结算事件；如果过程中意外关闭，恢复时须按明确的**中断投掷回滚/结算规则**处理（推荐先恢复未结算的圈并撤销未完成投掷），不能多扣或多加。
- 推荐原型使用**单份版本化持久化快照**或 IndexedDB 事务保存，避免“累计加了但鹅盘未标记”两份数据不一致。最终多人榜需由服务端校验。
- 【待测】网络/平台存储失败时可以展示“本地保存中/未同步”，不要先表现为成功保存然后丢失记录。

## 10. 成绩统计、准确率与排行榜

### 10.1 统计口径

| 指标 | 定义 | 用途 |
|---|---|---|
| `lifetimeCaught` | 全部正式模式有效套中总数 | 个人长期成就、全模式总榜 |
| `caughtNormal` | 普通鹅正式累计 | 普通鹅榜 |
| `caughtClever` | 机灵鹅正式累计 | 机灵鹅榜 |
| `totalThrows` | 全部正式投掷次数，不含练习 | 计算命中率 |
| `accuracy` | 有效套中次数 / 正式投圈次数 × 100% | 技巧指标 |
| `clearCount` | 历史清摊完成次数 | 成就指标 |
| `excellentClearCount` | 漂亮清摊次数 | 技巧成就 |
| `monthlyCaught` | 当月正式有效套中数，在每次成功后更新 | 月榜 |
| `practiceRingsRemaining` | 玩家剩余的独立免费练习圈 | 教学资源管理；不与正式库存混合 |

**定义细节**：一个圈最多计中一只鹅；砸中身体、挂圈不稳、被甩脱均不算。练习场不改变正式累计与命中率。所有正式累计在每次成功确认时即时入账，换盘/退出/清摊不再次加总。

### 10.2 榜单建议

- 榜单时间维度：**月榜 / 历史总榜**。
- 榜单难度筛选：**普通鹅 / 机灵鹅 / 全部**。
- 全部榜仅表示“套中总量”，受到游玩次数与资源影响，不应称为纯技巧榜。
- 【后续】好友榜可以提高社交性；省份榜需要足够用户量、区域数据授权与运营价值，不做 MVP。
- 【后续】命中率榜需要最低正式投圈门槛（比如 50 圈），并分难度统计，防止只套中 1 次就排第一。
- 月榜仅清空**月度榜统计窗口**，不清空历史累计。跨年月份按 `YYYY-MM` 记录，使用权威服务器时间规则，避免本地修改时间刷榜。

### 10.3 数据可信度

纯 H5 本地存档数据只能用于自测，不可直接作为可信全服排名。正式排行榜需要服务端接收投掷结果、限制重复计数、节流、校验经济库存；对重要比赛可以保存随机种子和投掷轨迹摘要，以利复核。无需首版就上复杂反作弊平台，但一定避免让客户端直接提交“累计 +9999”。

## 11. 游戏币、圈库存与广告：未定案的商业化设计

### 11.1 当前方向及已知条件

- 【确定】不采用“每局 20 圈”；正式套圈来自**可跨天保存的正式圈库存**。
- 【确定】练习场另用**有限练习圈**，首次免费额度建议 30，不消耗正式圈/币，也不计正式排行榜。
- 【当前优先方案，待经济测试】**庙会币 → 兑换正式套圈**。理由是与庙会的交易感相符、支持攒币，但多一步操作可能降低转化；若测试显示不必要，再退回“直接赠圈”。
- 【用户认可的起点数值，仍待测】每日可免费领取 **20 庙会币**，领取资格按运营日重置，币和正式圈库存本身不在午夜清零。
- 【确定的研发边界】广告位/平台接口提前预留；H5 验证阶段不接真实广告、不因圈数不足阻断物理/手感测试。
- 【参考游戏观察，不得直接搬运】普通分享 +10 币：用户观察为打开微信分享面板返回后似乎领取，仅一次；“广告分享 +30 币”机制未知。均不写成首版必须开发的功能。

### 11.2 币与圈的兑换测试建议

| 内容 | 候选规则 | 状态 |
|---|---|---|
| 每日领取 | 20 庙会币 | 用户认可方向；运营数值待测 |
| 基础兑换 | **20 币 → 20 圈** | 建议首个候选；容易理解 |
| 大额兑换 | **50 币 → 60 圈** | **新的差异化候选比例**，待测 |
| 币、圈存储 | 跨天保留 | 建议 |
| 库存上限 | 暂不设置低上限；必要时按运营数据增加 | 待定 |
| 激励视频 | 看完后获得一定币；数量、单次奖励及平台上限 | 待定 |

不建议直接沿用参考游戏的 **20/20 + 60/100** 完整组合。相同的简单兑换数字通常不能单独代表一款游戏的独创表达，但**盲目复制也没有设计价值**：更重要的是首轮投圈时长、玩家消耗速度、广告可达性和兑换摩擦。本文不是版权法律意见，涉及美术、台词、UI、角色及整体商业包装时应保持原创。

### 11.3 领币、兑换和补给入口如何布置

- **大厅/模式选择界面**：显示 `庙会币余额`、`领取今日 20 币`、`兑换正式圈`、`剩余正式圈`，玩家可以看到完整资源流。
- **游戏中轻量 HUD**：上沿只显示币余额的紧凑入口、剩余正式圈、当前盘 X/Y、个人累计；领取和兑换在小面板中进行，**不在出手轨迹或鹅颈前放大按钮**。
- **圈耗尽时**：允许打开补给面板或直接离开保留当前盘，不要求立即看广告。
- **练习场**：只显示练习圈余额 `X/30` 等信息，不混入正式币、圈与排行。
- **交易一致性**：兑换扣币与加圈应属于同一原子事务；领取每日币具有幂等键和运营日判定，不能反复点击/改系统时间重复发奖。

### 11.4 广告位预留（新增，不等于现在接广告）

| 场景 | 预留形态 | 初期原则 |
|---|---|---|
| 领币/补给面板 | 自愿观看激励视频领取庙会币 | 清楚显示奖励及剩余机会，未接入时隐藏 |
| 正式圈耗尽 | 提供可选“看广告领币”入口 | 同时提供退出/明日领取，不强制观看 |
| 清摊结算之后 | 可以评估非强制广告入口 | 不在清摊庆祝动画、关键命中时打断 |
| 大厅非操作区域 | 将来可评估轻量广告位 | 不遮挡模式、资源与玩法入口 |

正式平台适配层预留 `AdsService`（支持/加载/展示/完成/取消/失败/重复回调处理）和 `RewardGrantService`，但不在核心投掷代码里引用 `wx.*`、`tt.*`。广告请求失败时用户仍能正常退出或隔天领取资源。

### 11.5 分享与合规边界

- 玩家可以自愿分享套鹅累计、清摊记录和挑战链接；**不默认为分享成功立即给币**。
- 参考产品“分享 +10 币”的流程暂未证实其审核条件；类似功能能上线，不代表我们可依样实现。平台规则、奖励合规与技术校验均应在发布前专项核实。
- 广告奖励只能按平台允许的真实完成条件发放；失败、取消、频控、重复回调都要安全处理。
- 推荐先给玩家明确的个人记录与免费每日补给，再评估广告，不以“无限看广告才可正常玩”为目标。

### 11.6 后续应测试的经济问题

- 20 币兑换的 20 圈，普通玩家通常可以玩多久？会不会刚找到手感就没圈了？
- 币制是否真比直接赠圈更有趣？玩家是否看得懂币余额和圈余额的区别？
- 大额包是否过度诱导囤币而抑制当天游玩？
- 练习场 30 圈够不够？有限练习会不会让新手更不敢尝试正式模式？
- 广告入口能否自然产生选择，而不是阻断原本流畅的玩法？

**统一原则**：经济系统服务玩法；具体广告单次奖励、每日次数、币上限和正式兑换档位均可配置，**不得将候选数值硬编码成不可修改规则**。

## 12. 交互与 UI 说明

### 12.1 大厅/模式入口

建议首页直接展示鹅栏的实时场景，叠加简洁的操作入口：**开始/继续、练习、普通/机灵切换、领币、兑换、我的纪录、排行榜、设置**。为了不把鹅栏缩成小窗口，模式、领币和榜单可以放入可展开面板。

### 12.2 正式场 HUD 分级

| 层级 | 信息 | 推荐位置与行为 |
|---|---|---|
| 始终显示 | **正式圈剩余数、当前盘已套 X/Y、个人累计套鹅数** | 顶部薄信息条，左右分组，不盖住鹅头 |
| 轻量入口 | **庙会币余额 + 领币/兑换入口** | 顶部右侧紧凑入口，点击弹面板 |
| 情境显示 | 模式名、辅助状态、临时命中反馈 | 模式入口/暂停菜单和局部轻提示，不一直大字悬浮 |
| 非核心控件 | **设置、排行榜、玩法说明、模式切换** | 暂停/侧边菜单或大厅，避免压缩上沿操作视野 |
| 输入区 | 拉动蓄力、方向调整、投圈 | 下沿有效触摸区，禁用误触 HUD，显示力度/方向反馈 |

**不能强制把所有入口同时排列在游戏顶部。** 横屏手游右上角还可能有系统安全区和平台胶囊控件，先留空间再设计。

### 12.3 练习场 HUD

显示练习剩余圈 `X/30`、轨迹辅助切换、简短“怎么扔”提示与返回入口；不展示正式排行榜竞争或诱导购买。

### 12.4 成功、清摊与结算卡

- 单次套中：在持久化提交成功后显示 `+1 只` 并更新累计；不弹出强制结果对话框。
- 清摊完成：额外卡片展示当前盘 `8/8`、本盘使用圈数、历史累计（已经即时计数）、清摊次数、漂亮清摊情况、下一盘/返回选项。
- 主动换盘/圈不足退出：可以展示轻量本盘回顾，但**不重新发放历史数量**。

### 12.5 我的纪录与榜单入口

记录页展示总套中、总投圈、命中率、普通/机灵分模式数量和命中率、清摊/漂亮清摊次数。排行榜页面保留“月榜 / 历史总榜”以及“普通 / 机灵 / 全部”切换；好友 PK **仅预留说明位，不实现未定规则**。

### 12.6 设置与简易玩法说明

**设置中至少提供**：

- `背景音乐` 音量/静音；`庙会环境声` 音量/关闭；`鹅叫` 独立音量/关闭；`摊主语音` 音量/关闭；`操作/命中音效` 音量；总静音快捷入口。
- 辅助设置：练习轨迹显示级别、基础震动开关（若平台支持）、字幕开关（建议）。
- **玩法说明**（简短分栏即可）：`怎么扔`（方向/力度/轨迹）、`怎么算套中`（穿过头部且稳定挂在颈部）、`怎么计数`（正式套中立即 +1，练习不算）、`怎样上榜`（月/历史、普通/机灵，跨平台榜后端上线才开放）、`好友 PK`（预留/即将推出，不捏造规则）。
- 浏览器首次需用户交互才能解锁声音时，以安静进入并提供启用音效提示；离开、切后台、恢复遵循音频暂停规则。

### 12.7 排布与易用性验收

- 玩家手指主要操作区不得被币/广告/排行榜控件覆盖；主要鹅群在真实机型上不得被 HUD 盖住。
- 设置可以在游玩中进入，进入后暂停物理与计时；关闭后继续，不能重复扣圈。
- 音量调整后立即生效并保存；鹅叫与环境声能**真正分别关闭**，不是只关掉一条混音通道。

## 13. 音效、氛围和角色表达

### 13.1 音频分层

| 音层 | 例子 | 用户可调控制 |
|---|---|---|
| **背景音乐** | 轻量民间游乐音乐、节奏配乐 | 单独音量与静音 |
| **庙会环境声** | 人群交谈、远处叫卖、脚步、自然环境 | 单独开关/音量，轻声循环，不盖住投圈 |
| **鹅群叫声** | 短促俏皮“嘎？”、同伴轻声回应 | **独立开关/音量**，不使用惊恐或痛苦鹅叫，避免全员齐叫 |
| **操作音效** | 拿圈、出手、碰撞、落地 | 单独音量，精确对应碰撞时点 |
| **套中反馈** | 轻巧碰环声、成功提示、鹅得意小动作 | 避免“惨叫/挣扎”音色 |
| **摊主语音** | 招徕、惜败调侃、清摊惊讶 | 独立音量/静音，原创台词 |

原则：**不依赖鹅叫制造惨烈感，也不假设用户一定喜欢动物声音**。可以单独关闭鹅叫而保留其他游戏音效。

### 13.2 摊主声音（首版不强制方言）

【建议】自然、接地气、不尖叫。例：“哎哟，差那么一点！”“这只可机灵着呢！”“哎？真给你套着了！”“哟，快清摊了！”

可先用少量普通话/轻地方口音的原创音频测试；角色性别、年龄及具体口音**没有在本项目中确定**。与另一款游戏的河南话外星摊主设定不要自动合并。

### 13.3 音频事件规则

语音按重要程度分层：清摊/特殊事件最高、命中次之、普通闲聊最低。鹅的得意回应有独立事件冷却，不与摊主语音抢占关键听觉信息。背景音乐、庙会环境、鹅叫、摊主语音和操作音效分别提供音量/关闭，默认混音温和，避免突然大声齐叫。素材需保留商业使用权利与来源记录。

## 14. 技术路线与跨平台架构

### 14.1 选择理由

【建议】先用 **Three.js + TypeScript + Vite + Rapier 3D** 制作 H5 原型。它满足固定正交视角、真正 3D 鹅和套圈、物理碰撞，同时适合 AI Coding 的代码驱动工作流。该方案不是“完全没有游戏引擎功能”，而是以渲染库和物理库组装轻量游戏系统。

### 14.2 责任边界

| 层 | 责任 |
|---|---|
| Scene/Render | 相机、场景、模型、光影、UI 叠层 |
| Input/Aim | 横屏触控、投掷方向力度、辅助预览 |
| Physics | 刚体、重力、碰撞、接触事件 |
| RingJudge | 穿环几何、稳定时长、成功/失败、去重 |
| GooseAI | 漫游、群集、察觉、躲避、动画状态 |
| Vendor | 摊主动画、语音、后期鹅群指令 |
| Board | 鹅盘初始化、恢复、清摊、换盘 |
| Progress | 累计鹅数、投圈数、命中率、成就 |
| Economy | 有限练习圈、正式圈库存、庙会币、每日领取、兑换、广告奖励 |
| Platform | H5 / 微信 / 抖音特有存储、分享、广告、身份接口 |

### 14.3 游戏核心与平台隔离

`Game Core (TS + Three + Physics)` 与 `PlatformAdapter (Web / WeChat / Douyin)` 解耦。不要在物理与鹅 AI 代码里直接引用 `wx.*` 或 `tt.*`。游戏服务通过统一接口请求保存、领取广告奖励、分享、提交排行。

H5 可使用浏览器 DOM 做原型 HUD，但微信/抖音小游戏运行环境未必具备完整 DOM。要尽早验证小游戏 Canvas、触控、音频、资源、字体和 UI 兼容性，不承诺“普通 H5 页面原封不动打包即可发布”。

### 14.4 核心数据结构（示意）

```ts

type BoardState = {

type PlayerProgress = {

  totalThrowsClever: number;
```

这些只是接口层级的示意，不应在原型阶段一次性实现完整后端。

### 14.5 性能边界

- 【建议】首轮 8～12 只鹅，优先复用模型与动画；粒子与环境装饰有限量。
- 手机目标帧率先争取稳定 **30 FPS**，高端设备可向 60 FPS 优化；判定逻辑使用固定物理时间步，不能跟着 FPS 改变命中结果。
- 物理调试图层应能显示鹅颈 Collider、环碰撞体、预测路径、AI 感知区和冷却状态；正式版本隐藏。
- 实际性能、包体和内存限制以选定目标平台当前文档与真机为准。

## 15. H5 原型验证与开发里程碑

### P0 — 物理和防穿模技术实验

**内容**：正交相机、几何鹅头颈、套圈、地面、**足够大的围栏**、真实投掷、重力、套入判定、碰撞调试；补充圈↔鹅、圈↔围栏、鹅↔鹅、鹅↔围栏的验证。

**通过条件**：能够复现准确套入成功、撞头失败、侧面不能穿模、帧率变化结果稳定，鹅与鹅主躯干不能互穿。

### P1 — 带有限练习额度的可玩原型

**内容**：3～5 只静止/轻动鹅、轨迹+落点辅助、初始 30 练习圈（可配置 A/B 50）、倒数提示、简单友好反应、即时本次练习统计但不计正式累计。

**通过条件**：玩家懂得怎么扔、知道为何成功或失败、练习圈使用与恢复正确；开发者调试无限圈与玩家练习额度严格隔离。

### P2 — 正式模式与即时统计原型

**内容**：普通/机灵两种行为、8 鹅盘、清摊、继续/换盘、正式圈库存模拟、币与圈入口占位，**每次 CAUGHT 即时入账和原子存档**；新增 HUD 防遮挡和基本音量设置。

**通过条件**：单次套中关闭网页再打开累计不丢；不需清摊即可累积；切换模式正确恢复各自盘；无法重复计数；设置菜单不误投圈。

### P3 — 庙会氛围与动物友好精品样板

**内容**：不限定年代的民间庙会环境、宽敞整洁鹅栏、角落食物/饮水、小招牌、摊主走动、复用骨骼鹅群、有限俏皮反应、背景/鹅叫/摊主/音效各通道控制。

**通过条件**：鹅栏视觉上足够开阔；无动物痛苦画面与音频；关闭鹅叫/环境声均有效；手机真机无明显穿模与关键区域遮挡。

### P4 — 运营模型与多平台商业化（后续）

**内容**：币→圈兑换与每日领取、广告 SDK 适配预留、月榜/历史榜服务端、微信/抖音构建与后端基本反作弊，确认广告与分享平台规则。

**通过条件**：领取/兑换/广告奖励幂等；广告失败仍能退出/继续；排名不直接信任客户端累计；提交平台审核前检查动物友好内容和广告合规。

### P5 — 行为与社交扩展（可选）

**内容**：摊主正式指挥鹅、群体趣味反应、好友 PK 规则、节日活动、鹅王事件、省份榜等。只有在核心玩法完成验证后再扩展。

## 16. 必须覆盖的测试用例

| 编号 | 场景 | 预期结果 |
|---|---|---|
| T01 | 首次练习领取 30 圈并连续投掷 30 次 | 练习额度正确递减至 0；正式圈、币、正式累计不变 |
| T02 | 如启用每日练习补充，隔天再来 | 只按配置补充一次；不产生无限练习漏洞 |
| T03 | 圈正确穿过鹅头并在颈部稳定 | 当前盘 +1、对应模式 +1、总累计 +1，**立即持久化** |
| T04 | 套中后立刻关闭页面、第二天再打开 | 该鹅仍已套中，历史累计不回滚、不重复入账 |
| T05 | 只砸鹅头或鹅身 / 颈部侧穿 | 不能判套中；碰撞视觉与实际判定一致 |
| T06 | 鹅缩脖时套圈滑脱 | 稳定期之前不加鹅数、不进入清摊 |
| T07 | 同只鹅被多个圈反复触发 | 同一鹅盘鹅 ID 只能有效计数一次 |
| T08 | 多只鹅聚集、互相推挤、靠围栏转向 | 鹅躯干不交叉、不穿越围栏、不瞬移 |
| T09 | 圈碰围栏、地面、食槽、水盆、旧圈 | 不发生明显穿模；碰撞响应与可视模型对应 |
| T10 | 鹅头迅速歪转、低头、起身 | Collider 与骨骼位置同步；圈不穿颈 |
| T11 | 切换普通/机灵模式 | 各自盘面、各自正式累计保持一致，共用正式圈库存 |
| T12 | 中途退出、跨天继续和换盘 | 盘面正确恢复；历史累计不回滚；换盘不退圈 |
| T13 | 完成普通/漂亮清摊 | 清摊次数正确，本盘已记过的鹅不再重复加总 |
| T14 | 领币与兑换多次点击、刷新 | 币与圈的一致性可靠，不双发、不重扣 |
| T15 | 手指在 HUD 边缘、设置面板拖动 | 不误投圈、不遮挡关键鹅头区域 |
| T16 | 鹅叫关闭、环境声关闭、音乐音量调小 | 各通道独立生效、重启保持设置、不突然爆音 |
| T17 | 鹅的得意表情频繁触发 | 冷却有效，反馈不恶意辱骂玩家、不呈现动物痛苦 |
| T18 | 低端手机掉帧 / 切后台恢复 | 物理稳定，不穿模、不重复扣圈/加鹅 |
| T19 | 广告取消/失败/完成重复回调 | 只在符合平台条件时单次发奖，不死锁 |
| T20 | 修改客户端日期或本地累计 | 服务端榜单不能直接相信客户端任意数值 |
| T21 | 不同横屏比例、平台安全区 | 鹅栏主体占比合理、控件不挡操作区 |
| T22 | 连续 100 次落圈压力测试 | 主要碰撞链路无明显穿模、稳定计数、性能可接受 |

## 17. 游戏体验验证指标（不把数值当 KPI 承诺）

重点观察，不预设成功率目标：

1. 玩家能否很快理解投圈方向与力度？完整轨迹/落点环是否真有帮助？
2. 不同手机下是否看得清鹅颈、圈的飞行、落点与鹅群距离？围栏是否足够突出？
3. 视觉上是否有任何明显穿模或“看起来命中却判失败”的情况？
4. 普通和机灵是否具有可学习的差异，而不是随机闪避令人觉得作弊？
5. 玩家是否理解**套中立即累计**，即使退出/次日继续也不会丢失？
6. 30 个免费练习圈够不够？如果不够，玩家是否因为额度不足而害怕进入正式场？
7. 鹅的“得意反应”是增添趣味还是引人烦躁？是否有玩家对套鹅题材本身不适？
8. 关闭鹅叫和庙会环境声以后，玩家能否舒适地玩完整个过程？
9. 庙会币与圈库存的关系是否直观？广告/领币入口是否抢走玩法焦点？
10. 清摊、命中率、累计鹅数是否给玩家足够复玩理由？

建议邀请 5～10 名真实手机试玩者，记录操作理解、失败归因、主动重玩、动物友好感受和付费/广告摩擦的具体反馈；不要只询问“好玩吗”。

## 18. 风险、取舍与未来决策

| 风险 | 为什么重要 | 当前处理 |
|---|---|---|
| **动物伤害感 / 舆论反感** | 游戏题材可能被视作欺负真实鹅 | 风格化鹅、无疼痛音画、宽松彩环、食水环境、专项测试 |
| **环真实套入活动颈部** | 物理、动画与几何同步复杂 | 先做灰盒，锁定 RingJudge 规则 |
| **鹅 ↔ 鹅 / 圈 ↔ 围栏穿模** | 破坏公平性与品质 | Collider 接触、Boids 避让、CCD、固定步长、专项测试 |
| **鹅躲避像系统作弊** | 玩家丧失学习动力 | 明显前兆、延迟、动作冷却和日志 |
| **38° 正交镜头落点难判断** | 影响投掷学习 | 30/38/45 比较 + 投掷辅助 |
| **练习额度过少** | 阻断新手上手 | 先测 30 对比 50、保留少量复习兜底 |
| **币与圈两层资源增加学习成本** | 兑换步骤影响留存 | 币制先做可替换实验，不把档位写死 |
| **广告入口遮挡游戏** | 影响屏幕有效面积和误触 | 预留在大厅/补给面板，射击时不弹出 |
| **即时累计但存档不一致** | 刷新页面会丢失/双发鹅数 | 投掷 ID 幂等、原子提交、盘面数据一致 |
| **累计榜受游玩时长影响** | 不代表纯技巧 | 分模式/月榜，准确率作个人指标 |
| **H5 适配小游戏成本** | DOM、音频、输入差异 | 早期平台冒烟测试与 Adapter |
| **美术音频版权** | 商业上线风险 | 原创设计、素材来源和商用权核验 |

### 18.1 本轮明确收敛的方向

- 不将年代限定为 1990 年代，只保留中国庙会与民间游乐摊氛围。
- **鹅栏为视觉主体**，摊主在围栏内安全活动带；保留小招牌，食槽/饮水盆作为动物友好装饰；避免大棚与杂乱陈列抢空间。
- 动物友好的互动表达是必须遵守的设计边界；鹅得意、调皮的反应仅为待测试的趣味点。
- 练习场使用**有限**免费练习圈，初始建议 30（对比测试 50），不计正式榜；开发调试无限圈不对玩家开放。
- 正式模式不强制一局 20 圈，**每只鹅稳定套中立即计入长期统计并可靠持久化**。
- 正式两种难度（名称可再改）、每盘暂定 8 只、围栏/鹅群/圈间明显穿模不可接受。
- 需要设置、玩法说明、模式、榜单、币与圈入口，但分层显示避免 HUD 拥挤；音频需支持音乐、环境、鹅叫、摊主、操作反馈分通道控制。
- **币制兑换为当前优先候选**，每日 20 庙会币为用户认可的首轮配置，广告位预留；尚未核实的分享奖励不落地。

### 18.2 仍需通过原型确认

投掷手势 A/B；相机最终俯视角；正式鹅盘 8 只是否偏少；鹅外观尺寸与安全间距；圈内径/重量/倾角、稳定期、AI 参数；练习 30 对 50 的体验；是否每日追加少量练习额度；鹅得意反馈是否受欢迎；不同难度正式辅助的允许级别；大额兑换比例；摊主模仿/赶鹅是否有必要。

### 18.3 继续暂缓的运营事项

- 激励视频每次给币数、观看上限、资格及频控；具体广告展示形式须按平台后台和审核规则测试。
- 分享 +10 币：用户观察到一次性打开面板似乎返币，但**实现机制、审核条件不明**。
- “广告分享 +30 币”：真实触发过程未观察到，保持待定。
- 好友 PK 的交互、挑战结算、好友关系权限；省份榜和跨平台统一用户身份；正式服务端排行与安全模型。

本 GDD 回答“**我们要做什么游戏，为什么，规则是什么**”。下一份应当是独立的《H5 物理可玩原型执行说明（P0–P2）》，而不是继续扩写世界观。它只需要给 Codex：项目启动命令、物理实验场景、围栏/鹅群碰撞约束、投圈输入映射、RingJudge 状态机、30 个练习圈、即时累计存档、可调参数、每步验收与回退策略。
