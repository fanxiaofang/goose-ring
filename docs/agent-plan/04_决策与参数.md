#### P0-1 决策记录

**D-20261123-001 真实有孔套圈的碰撞方案**
- 需求来源：02_阶段任务.md P0-1、AGENTS.md §5；P0-0 评审要求“不能用球体代替、不能只有视觉内孔”。
- 备选：实心圆盘 Collider（否决，中心无法穿过）；Torus 网格凸包（Rapier 无原生 torus，凸包会填满内孔）；16 段胶囊环（采用）。
- 最终选择：16 段胶囊围成闭合环，段间圆帽重叠，内孔净半径 0.375 m。
- 状态：已确认（几何与物理单测均通过）。
- 受影响文件：`src/ring/ringGeometry.ts`、`src/ring/ringBody.ts`、`src/physics/PhysicsWorld.ts`、`src/ring/RingSystem.ts`。
- 回退方案：若真机稳定性不足，可增减段数或改多面体环，但不得改为实心盘。

**D-20261123-002 相机取景测试改为屏幕构图验收**
- 需求来源：P0-1 评审遗留问题 5。
- 证据：旧断言只比较“注视点平面可视高”，无法反映围栏顶部 UI 带、前栏位置与鹅头安全区；且 P0-0 后期主动收紧透视取景，使 1.1 m 容差失去意义。
- 最终选择：直接投影围栏四角与实验鹅头到屏幕百分比，验收顶部/底部 UI 安全带与围栏占屏；A、B 纳入正式候选断言，C 保留实验。
- 状态：已确认。
- 受影响文件：`src/cameraUtils.test.ts`。

**D-20261123-003 P0-1 单鹅测试场景与固定投掷**
- 需求来源：P0-1 评审“优先使用单只静止鹅进行套圈实验”“保留确定性测试条件”。
- 最终选择：`?geese=single` 用离玩家最近的鹅，视觉与 Collider 同步缩减；固定投掷全部写死参数、无随机项；`?throw=` 与“重放上次”使用完全相同的初始条件。
- 状态：已确认。
- 受影响文件：`src/app/GameApp.ts`、`src/ring/throwPresets.ts`、`src/physics/PhysicsWorld.ts`、`src/scene/GameScene.ts`。

## 5. 重要尚未解决的技术/设计问题

1. **真实有孔物理圈是否能稳定越过带动画的鹅头？** P0-1 已证明静态鹅头/鹅颈可穿过（净孔 0.375 m > 头 0.15 m、颈 0.1 m），但带动画鹅头、正式套中判定与“套住后再被拖走”仍属 P0-2，未验证。
2. **正式资源中断时怎样处理？** v1.1 倾向未结算投掷退圈，可能被故意刷新套利；P2 要实验并说明运营风险，商业版另定服务端或权威结算规则。
3. **轨迹辅助是否允许出现在正式排行？** 目前练习默认 full，正式辅助规则待测，必须存 assistLevel。
4. **玩法是“投圈有真实重量感”还是“更宽容的休闲抛物”？** 先以可信物理为基础，调整容错需记录。
5. **板内鹅数量 vs 镜头遮挡**：8 是候选，不可因设备不同产生判定不一致。
6. **动物友好表达**：需要观察受众反馈，不以开发者认为“可爱”代替外部测试。
7. **正式相机 A/B 取舍**：按评审要求，需用真实套圈投掷对比 A 正交与 B 透视 25° 的手感后再定；本轮只保留切换能力，不切默认相机。
